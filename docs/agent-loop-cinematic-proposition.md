# Agent loop — 시네마틱 설명 연출 개정

2026-09-08, 구현 전. **EXPERIMENT**. 기존 `agent-loop-proposition.md`의 이력과 검증은 유지한다.

## 확정된 의도

사용자는 이전 시연에 대해 “3D가 무늬만 3D여서 시인성이 떨어지고 뭘 하는지 모르겠다”고 평가했다. 사진을 정면으로 크게 보여주고, 탐색 요청 → 도구 작업 → 관찰 반환 → 다음 행동 변화가 화면에서 읽히는 개정을 승인했다. 추상 agent 형태를 유지하고 카메라 움직임도 시네마틱하게 만든다. 발표용 재생·단계 이동·정지와 실제 실행을 가장하지 않는 조건은 유지한다.

## 개정 이유와 가설 리뷰

초기 명제의 기술적 검증 PASS는 의미 전달의 성공을 입증하지 못했다. 사용자의 피드백을 근거로 구도·시선 유도·행동 표현을 개정한다. 관찰 가능한 조건을 낮추지 않으며 사용자 승인으로 범위를 구체화한다.

가설: 작은 바닥 사진과 전역 작업대를 대신해, 현재 행동을 하나의 촬영 장면으로 구성한다. 정면 사진, 내용이 쓰인 요청/관찰 전달, 사진 위 증거 표시가 동작의 뜻을 전달한다. 입체 agent는 작업 대상에 반응하며, 카메라는 검색의 넓은 구도 → 확인의 접근 → 피드백의 추적 → 결과의 물러남을 사용한다. 이동 뒤에는 읽을 수 있는 정지 구간을 둔다. **SOUND**: 승인된 방향에 대응하고 별도 브랜치로 되돌릴 수 있다. 자동 검사는 가독성의 물리적 조건을 확인하며 실제 이해도 확정은 사용자 판단으로 남긴다.

## 관찰 가능한 결과·불변 조건

- 정지한 주요 장면에서 현재 agent, 행동, 사진/요청/관찰을 함께 확인한다. 데스크톱 비교 사진 너비는 190px 이상, 설명 라벨은 12px 이상을 목표로 한다.
- 사진은 카메라를 향해 읽기 쉬운 상태를 유지한다. 현재 장면에 필요 없는 agent는 주변 표시로 대기한다.
- 실제 카메라 위치·거리 변화가 사진과 agent 구도에 함께 반영된다. 카메라 흔들기나 무한 회전 없이 장면마다 안정적으로 정착한다.
- 탐색 요청에는 도구/요청 내용, 반환에는 후보 정보 또는 실제 이미지가 보인다. 반환 관찰은 다음 행동 선택 장면에도 남는다.
- 검토의 구체적인 피드백이 원래 Explorer에게 돌아가고 이후 검색 요청이 달라진다. 원본 대상, 네 번의 도구 왕복, 한 번의 조건부 재탐색, 최종 후보 [1,2]는 유지한다.
- 검토 이전의 후보를 통과 결과로 표시하지 않는다. 원본 0과 탈락 후보 [4,3]은 최종 결과에서 제외한다.
- 일시정지는 카메라·agent·사진·전달 표시를 모두 고정한다. 임의 단계 이동과 움직임 축소 환경에서는 해당 장면의 읽을 수 있는 완성 구도로 이동한다.
- 배속에서도 장면을 건너뛰지 않는다. 종료 시 정지, 숨긴 탭 정지, 로컬 자산, WebGL 실패 대체 화면을 유지한다.
- 제품 서버·Android 코드는 변경하지 않으며 기존 시연 브랜치와 worktree는 보존한다.

## 검증 계획

1. 데스크톱·좁은 화면에서 주요 장면을 캡처하고 사진 크기, 표시 겹침, 행동과 대상의 연결을 확인한다.
2. 재생 중 실제 카메라 구도 변화와 정착을 관찰하고, 일시정지 전후 canvas 및 사진/전달 표시 위치가 같은지 확인한다.
3. 도구 요청/응답 내용, 관찰 유지, 피드백 이후 검색 요청 변화와 최종 사진 구성을 브라우저에서 검사한다.
4. 19단계 전체 재생·수동 이동·재시작·배속·축소 동작·대체 화면·외부 요청 없음의 회귀 검증을 실행한다.
5. 명제와 증거를 대조한 구현 리뷰, 커밋·푸시, 사용자 미리보기까지 완료한다.

## 실행 증거

최종 실행: 2026-09-08 17:06 KST, Edge 152.0.4191.66 / Playwright. 전체 결과와 측정값은 `agent-loop-cinematic-validation.json`에 기록했다.

1. **기능·구도:** 시작·검색 수정·검토 미통과·검토 통과·완료·대체 화면을 캡처했다. 1440/1024px 비교 사진 너비는 220.45–240.13px이며 캡션은 12px이다. 760/390/360/320px에서도 주요 장면의 사진·표시와 행동 제목이 화면 안에 있고 가로 넘침이 없었다. 사진을 정면으로 배치하고, 렌즈가 사진 위를 이동하며 비교하는 장면과 작은 화면의 배치를 육안 확인했다. 사진 위 상자·판정은 시연용 주석이다.
2. **카메라·재생:** 원근 카메라의 위치·거리와 사진 투영을 동일한 재생 시간으로 갱신한다. 검색의 측면 이동, 이미지 확인의 접근, 전달·피드백의 추적, 완료의 물러남을 구현했다. 자동 7→8단계 전환에서 canvas와 전달물·이름표 위치가 변하는 것을 관찰했다. 일시정지 후에는 canvas 캡처가 바이트 단위로 같고 사진·전달물·이름표의 경계 좌표가 모두 동일했다. 별도의 애니메이션 타이머로 재생 상태가 어긋나지 않는다.
3. **설명의 인과관계:** 네 번의 관찰 반환과 한 번의 검토 피드백에 서로 다른 이름·내용·방향이 붙는다. 2→3 및 11→12단계에서 받은 관찰 문구를 유지하며 다음 요청이 사진 확인으로 바뀐다. 9단계에는 원본만, 재검색을 실행한 10단계부터 새 후보 [1,2]가 등장한다. 검토 이전에는 통과 표시가 없고, 최초 미통과 [4,3]과 원본 0은 최종 결과에서 제외한다. 제출 장면에서는 실제 구도에 보이는 수신자 Reviewer를 표시한다.
4. **회귀 증거:** 19단계 전체를 2×로 순서대로 재생하고 마지막 장면에서 멈춘다. 이전/다음/슬라이더/장면 선택/재시작과 방향키/Home을 검증했다. 임의 단계 이동은 이전 경로와 무관하게 같은 정착 구도를 보여준다. 움직임 축소의 자동 시작 방지, 실행 중 축소 설정으로 전환할 때 정지, 3D 모듈 실패 대체 화면을 검사했다. hidden/visibilitychange를 모사하면 멈추고 자동 재개하지 않는다. OS 창 전환 자체를 검사한 것은 아니다. 잡히지 않은 브라우저 오류와 외부 런타임 요청은 0건이다.
5. **리뷰·빌드 게이트:** JavaScript 구문 검사와 `git diff --check` 통과. 초기 검사에서 중간 폭의 사진 잘림을 수정했고, 소급 검토에서 발견한 ‘검색 전에 새 후보 노출’과 ‘제출 장면의 이름표·실제 agent 불일치’를 수정한 뒤 전체 브라우저 검증을 다시 통과했다. 서버·Android 파일은 변경하지 않아 해당 전체 테스트는 실행하지 않았다.
