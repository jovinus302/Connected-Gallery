# Agent loop — embodied choreography

## 변경 명제 · 2026-09-09 · EXPERIMENT

### 확정된 의도
사용자가 발표 시연을 볼 때 추상적인 agent가 직접 일하는 존재로 느껴져야 한다. 사진을 다루는 행동과 도구 왕복·독립 검토·피드백 이후 재탐색을 볼 수 있어야 하며, 입체 공간과 행동을 따라가는 시네마틱 카메라가 필요하다. 사용자는 이전 버전의 시인성, 입체감, 행동 주체와 카메라 연출이 부족하다고 평가했다.

### AI의 해석·가설
사진이 평면 DOM이고 agent와 독립적으로 보간되는 점이 주요 원인이다. 실제 두께를 가진 사진 mesh와 공통 바닥·그림자·배경, 접촉/운반/놓기 동작으로 인과를 만들고, 행동 중심의 3/4 구도·호 이동·근접 구도·전달 추적을 사용한다. Explorer는 위성 그리퍼로 꺼내고 전달하고, Reviewer는 사진을 렌즈에 정렬하여 확인하며, Organizer는 모듈을 펼쳐 결과를 받는다. 좁은 600px 패널에서도 주체와 대상이 함께 크게 보여야 한다.

배제한 대안: 사진 div에 원근 효과만 더하기, agent의 제자리 회전 확대, 의미 없이 카메라만 계속 돌리기, 실시간 모델 연동, 새로운 캐릭터/이미지 생성. 기존 소재·Three.js·19단계 시나리오·재생기를 재사용한다. 별도 worktree와 브랜치로 되돌릴 수 있게 한다.

### 관찰 가능한 결과 / 검증 계획
1. 집기 전 → 접촉 → 운반 → 놓기의 단계가 보이며, 운반 중 그리퍼는 카드 가장자리와 결합한다. 검색 반환·제출·정리를 시간별 캡처와 위치 측정으로 확인한다.
2. 사진은 두께 있는 mesh이고 전후 배치·옆면·가림·바닥 그림자가 존재한다. 정지 화면과 카메라 이동을 600px/1440px에서 관찰한다.
3. 카메라는 전체/중간/근접 구도와 높이·방향이 다른 곡선 경로를 가지며, 행동 대상이 프레임 안에 남고 판독 시간이 있다. 시작/검토/전달/완료 화면 및 연속 재생을 확인한다.
4. 네 번의 도구 왕복, 한 번의 검토 귀환, 원본 유지, 수정 검색 전 새 후보 미노출, 최종 후보 [1,2]를 기존 fixture와 단계별 화면으로 확인한다. 검토 판정은 렌즈 확인 뒤 나타난다.
5. 일시정지 시 카메라와 모든 오브젝트가 정지하고, 단계 선택은 읽을 수 있는 결정적 구도로 이동한다. 마지막 장면 정지, 축소 동작, 좁은 화면, 대체 화면과 브라우저 오류를 검증한다.

### 불변 조건
고정 시연임을 표시한다. 내부 사고/실제 실행 기록으로 표현하지 않는다. 시연 외 서버/모델/사진 데이터 변경 없음. 재생·속도·단계·키보드·설명 조작을 유지한다. 원본과 최종 결과 의미를 유지한다. 기존 버전과 사용자 변경을 보존한다.

### 미결정 사항
동작과 촬영이 사용자가 원하는 느낌에 도달했는지는 사용자 감상으로 확인할 제품 가설이다. 테스트 통과를 그 감상의 증거로 대체하지 않는다.

### 가설 리뷰
SOUND: 이전 원인을 agent-물체 결합과 실제 공간으로 직접 변경한다. 역할별 행동, 프레임의 가독성, 루프 의미와 조작을 각각 검증하며 새 모드나 실행 정책을 추가하지 않는다.

## 실행 증거

2026-09-09, Microsoft Edge 152.0.4191.66에서 `node scripts/verify-agent-loop.cjs http://127.0.0.1:8893` 최종 PASS. 전체 로컬 실행값은 `work/agent-loop-validation/result.json`, 재현 가능한 요약·대표 프레임은 [agent-loop-embodied-validation.json](agent-loop-embodied-validation.json)에 기록했다.

1. **접촉과 운반:** 실제 렌더 프레임의 그리퍼 끝·카드 모서리 간 최대 오차는 4.45e-16 world units. 도구 반환·제출·검토·정리에 결합 프레임이 있고, 결합 중 Explorer 제출 카드가 약 5.36~5.81 units 이동했다. 놓기 뒤 attached=false를 확인했다. Reviewer도 카드 위치가 변하는 동안 접촉하는 프레임을 관측했다. 이 수치는 움직임 결합의 증거이며 생명감의 정량 점수가 아니다.
2. **입체와 가독성:** 사진은 깊이 0.14의 프레임 mesh이며 독립적인 사진 텍스처와 옆면을 가진다. 실제 투영된 비교 사진 너비는 1440/1024 화면에서 222~241px, 600 화면에서 155~164px, 320 화면에서 107~109px. 6개 폭(1440/1024/760/600/390/320)에서 활성 mesh와 캡션이 프레임 안에 있고 가로 넘침이 없었다. 캡션 12px 유지. 실제 600/320 패널과 검증 PNG에서 옆면·바닥 그림자·단상·카드 가림을 시각 확인했고 겹치던 이름표를 옮겼다.
3. **카메라:** 높은 시작 구도, 낮은 측면 전달, 렌즈 중심 검토, 마지막 상승 후퇴를 구현했다. 연속 재생에서 카메라 높이 차 5.03 units, 마지막 장면의 시선 대상과 거리 증가 5.13 units를 관측했다. 마지막 장면이 progress=1까지 재생되고 멈춤을 확인했다. 시네마틱 감상의 충족 여부는 사용자 피드백으로 판단할 가설이다.
4. **Loop 의미:** 19단계 모두에서 행위 주체·요청·응답을 확인했다. 도구 반환 4회와 검토 귀환 1회를 구별한다. 9단계는 원본만, 수정 검색 10단계부터 새 후보 [1,2]. 최종 [1,2]는 원본과 미통과 후보를 제외한다. 판정과 표시가 렌즈 확인 이후에 나타나는 소스와 정착 화면을 대조했다.
5. **조작과 회귀:** 재생/정지/단계/키보드/설명/속도, 전체 2배속 순서, 모듈 실패 대체 화면, 축소 동작, 탭 숨김 이벤트를 검증했다. 정지 중 canvas와 모든 진단 transform·캡션 위치가 같았다. 마지막 장면 중간 일시정지→재생이 18단계를 이어가고 완료 뒤에만 처음부터 재생한다. 브라우저 예외와 외부 runtime 요청 0건. JS 문법·diff 공백 검사 통과. 변경 없는 서버/Android 검증은 실행하지 않았다.

### 실행 중 보완 · 2026-09-09
이전 재생기가 마지막 장면 진입 즉시 멈춰 카메라 후퇴를 생략하는 문제를 발견했다. 마지막 장면의 길이를 끝까지 재생하도록 변경하고, 완료와 일시정지를 `finished`로 구분하여 마지막 장면에서도 이어보기를 유지했다. 또한 동일 단계 재선택을 완성 구도로 정착시키고, 수동 선택 후 재생은 해당 동작을 다시 보여준다. 관찰 조건을 낮추지 않는 수정이다.
