# Agent loop 시연 화면 — 변경 명제

작성: 2026-09-08, 구현 전. 변경 성격: **EXPERIMENT**.

## 확정된 의도

사용자는 승인한 생성 이미지의 추상 agent(파란 유기체, 호박색 렌즈, 검은 모듈)를 실제로 움직이는 발표·시연 화면으로 볼 수 있어야 한다. Agent loop 구조가 눈에 들어와야 하며, 재생과 단계별 관찰이 가능해야 한다. 제품의 사진 검색 및 Android 동작은 유지한다.

## AI의 해석·가설

기존 HTML 발표 자료 옆에 독립적인 브라우저 시연을 둔다. 넓은 밝은 작업대 위의 입체 agent와 사진 이동으로 역할을 표현하고, 행동 선택 → 도구 실행 → 결과 관찰 → 다음 행동 선택의 순환을 움직이는 궤도와 단계 표시로 설명한다. 독립 검토의 조건부 재탐색은 다른 귀환 경로로 표현한다. 가상 시나리오임을 상시 표시한다.

정적 흐름표만 보여주는 안은 사용자가 배제했다. 실제 서버 이벤트 연결은 사용자가 발표·시연용을 선택했으므로 이번 범위가 아니다. 제품의 내부 사고를 재현한다고 주장하지 않고 관찰 가능한 도구·결과·피드백의 시연만 제공한다.

## 관찰 가능한 결과와 불변 조건

- 실제 3D agent 세 개가 각각 탐색·검토·정리 역할을 수행한다.
- 도구 관찰에서 탐색 agent로 되돌아오는 내부 loop와 검토 피드백의 재탐색 경로를 구분한다.
- 일시정지, 재개, 앞/뒤 단계, 처음부터 재생, 단계 선택이 하나의 시연 상태를 공유한다.
- 끝에서 멈추며, 숨겨진 탭에서는 자동 진행하지 않는다. 움직임 축소 환경에서는 자동 재생하지 않는다.
- 사진은 기존 발표의 생성 이미지이다. 네트워크·모델 호출, 실제 개인 사진 접근, 서버 변경을 하지 않는다.
- WebGL이 없거나 로드에 실패해도 명시적인 대체 화면과 단계 설명·조작을 제공한다.
- 내부 loop는 `agent_runtime/runner.py`의 model/tools 왕복에 대응한다. 검토 후 재탐색은 최초 검토에서 지원된 후보가 없고 결과가 불완전하며 원본 대상이 유효하고 남은 예산이 있을 때 한 번 허용되는 분기에 대응한다. 무한한 reviewer→explorer 루프로 표현하지 않는다.
- 최종 정리는 `result_organizer`가 연결된 구성의 동작이다. 오래된 Spaces organizer와 혼동하지 않는다.

## 검증 계획

1. 브라우저에서 3D 렌더링, agent 구분, loop 궤도와 피드백 귀환을 시각 확인한다.
2. 단계 이동·일시정지·재개·종료·재시작·배속의 관찰 결과와 표시 동기화를 확인한다.
3. 검토 전 후보와 재탐색 후 확인된 사진의 구분, 종료 상태, 재탐색 횟수를 확인한다.
4. 좁은 화면의 넘침, 키보드 조작, 움직임 축소, WebGL 실패 대체 화면을 확인한다.
5. 자산을 로컬로 묶고 런타임 외부 요청이 없음을 확인한다. 변경 diff를 검토하고 커밋·푸시한다.

## 가설 리뷰

**SOUND** — 승인된 시각 방향과 발표 목적에 직접 대응하며, 기존 발표 자료와 제품 동작을 보존한다. 독립 폴더를 제거하거나 링크를 되돌리면 취소 가능하다. 실제 agent 실행을 보여주는지는 이번 실험의 성공 주장이 아니다.

## 미결정 사항

실제 실행 이벤트 연결과 Android 화면 적용은 별도 제품 결정이다.

## 실행 증거

검증 시각: 2026-09-08 16:31 KST. 브라우저: Microsoft Edge 152.0.4191.66, Playwright. 결과 원본 요약은 `agent-loop-validation.json`에 보관한다.

1. **기능·시각 증거:** 1440px 화면에서 실제 WebGL canvas와 세 agent를 확인했다. 탐색 관찰 단계 2/5/11/14에서 관찰 표시가 활성화되고, 단계 8에서 호박색 귀환 경로가 나타난다. 시작·관찰·검토 귀환·완료 화면을 캡처해 육안 확인했다. 이 증거는 시연의 전달 방식에 대한 것으로 실제 검색 품질을 입증하지 않는다.
2. **재생 증거:** 이전/다음, Home/방향키, 슬라이더, 재시작, 2× 재생, 일시정지를 브라우저에서 조작했다. 연속 2× 재생에서 0부터 18까지 모든 단계를 순서대로 관찰하고 마지막 단계의 정지를 확인했다. canvas 캡처가 재생 중에는 달라지고 일시정지 중에는 바이트 단위로 동일했다. 초기 검사에서 일시정지 중 불필요한 다시 그리기를 발견해 중지하도록 수정한 뒤 전체 검증을 통과했다.
3. **시나리오 불변 조건:** 최초 검토의 후보 두 장은 미통과로 표시되고 최종 검토의 새 후보 두 장은 통과로 표시된다. 선택 원본은 결과 썸네일에 포함되지 않는다. 검토 피드백은 한 번이며, 최종 단계는 관련 사진 두 장으로 끝난다. 이 판정은 설명용 fixture의 동작이다.
4. **경계·접근성:** 1024/760/390/360/320px에서 가로 넘침과 장면 라벨 잘림이 없음을 확인했다. 움직임 축소 환경에서 자동 시작이 없고 단계 이동이 가능했다. 3D 모듈 로드를 실패시키면 콘셉트 대체 화면과 단계 조작을 사용할 수 있었다. visibilitychange와 hidden 상태를 명시적으로 모사한 검사에서 정지 후 자동 재개가 없었다. 실제 OS 창 전환 검사는 수행하지 않았다.
5. **회귀 방지·빌드 게이트:** 프로젝트 서버와 Android 파일을 변경하지 않았다. 로컬 JavaScript 구문 검사와 `git diff --check` 통과. 브라우저에서 잡히지 않은 오류와 외부 런타임 요청은 0건. 모든 이미지와 Three.js를 로컬에 포함했다. Python/Android 전체 테스트는 실행하지 않았다. 이번 변경의 게이트는 독립 시연의 브라우저 검증이다.

## 구현 리뷰

**PASS / EXPERIMENT**. 확정된 발표용 시연 의도와 두 종류의 loop가 구현됐다. 내부 loop와 검토 귀환을 하나의 무한 loop로 오해하지 않도록 장면·설명·종료 상태를 구분했다. 기존 발표의 생성 자산과 독립 정적 자료라는 프로젝트 방향을 따른다. 실제 agent 실행 연결, 사진 검색 품질, 이 디자인의 사용자 이해도 검증은 이번 PASS의 주장이 아니다.

확인 방법: `docs/presentations/agent-loop/start.ps1`을 실행하고 표시된 로컬 주소를 연다. 「검토와 피드백」 장면에서 다음 단계를 눌러 귀환을 확인하고, 재생 버튼으로 완료까지 이어본다. 재현 가능한 자동 검증은 `scripts/verify-agent-loop.cjs`다. 남은 제품 결정은 실제 실행 이벤트 연결과 Android 적용이다.
