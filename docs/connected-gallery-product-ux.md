# Connected Gallery — Connect와 사진 맥락 UX

2026-09-07 제품 결정 · 2026-09-08 구현 상태 갱신. 이전 Android 검증은 [통합 검증](context-ux-validation.md), 합성 PC 데모는 [데모 완료 기록](pc-demo-completion.md), 두 구현을 합친 소스의 검증과 v6 계약은 [머지 기록](demo-main-integration.md)을 따른다.

## 1. 제품의 중심

**사진 속 대상을 따라가며, 도착한 사진의 맥락을 이해하고 다시 탐색하는 갤러리.**

Connect는 관심 대상을 탭해 관련 사진을 찾게 한다. Organize는 사용자가 연 사진 주변의 의미 있는 관계를 펼쳐, 그 사진을 이해하고 다음 탐색을 선택하게 한다. 두 기능은 하나의 경험이다.

Organize는 MVP의 핵심 역할로 유지한다. 단순한 결과 분류 효율이나 그룹 개수로 필요성을 평가하지 않는다. 사용자가 사진 사이의 관계를 이해하고, 다음에 보고 싶은 것을 발견하는 데 기여해야 한다.

### Space 제외 결정 — 2026-09-07

Space를 MVP에서 제외한다. 사용자에게 제공하는 Space의 생성·자동 게시·저장·목록·편집과 사용자 쓰기 권한 모델은 이번 구현 범위와 완료 조건에 포함하지 않는다. 자동 묶음 홈만 제외하고 탐색 결과를 Space로 저장하는 기능을 남기는 것으로 해석하지 않는다.

Organize는 핵심 역할로 유지한다. 사진을 열면 에이전트가 근거 있는 주변 맥락을 구성해 보여주고 다음 탐색으로 이어지게 한다. 이 동작은 Space 생성이나 영구 저장을 요구하지 않는다.

준비된 연결·맥락의 내부 저장 및 캐시, 버전·무효화·복원은 유지한다. 이는 사용자가 이름을 붙이고 관리하는 영구 묶음과 별개의 인프라다. 향후 다시 방문할 탐색을 저장할 필요가 확인되면 사진 묶음·맥락·탐색 경로 중 무엇을 저장할지부터 별도로 결정한다. Space 재도입을 예정된 후속 작업으로 두지 않는다.

Space 제외는 후속 코드 변경으로 반영했다. Android의 Spaces 모듈·진입·모으기·관련 호출을 제거했고, 서버의 목록 API·새 Organizer 실행·Space 편집·자동 생성을 차단했다. 재시작 시 기존 대기 중 Organizer 작업은 취소한다. DB·저장 데이터와 과거 검증용 서버 내부 타입·도구는 보존하되 활성 Explorer에 Space 도구를 제공하지 않는다. [Space 제거 검증](space-removal-validation.md)을 참조한다. 사진 상세 맥락 구현·품질·성능은 각 버전의 별도 검증 기록을 따른다.

## 2. 확정한 사용자 흐름

**대상 탭 → 관련 사진 표시 → 사진 한 장 열기 → 사진과 함께 맥락 표시 → 다음 탐색**

1. 사용자가 사진 속 와인을 탭한다. Connect가 선택한 와인과 관련된 사진을 보여준다.
2. 결과 중 식당 사진을 연다. 사진이 크게 보이고, 바로 아래에 그 사진의 맥락과 관련 사진 미리보기가 나타난다. 여기서 Organize를 마주한다.
3. 그날 함께 찍은 사진이 의미 있는 근거라면, 그 사진들을 별도 요청 없이 볼 수 있다. 전체 목록을 펼치기 위한 추가 조작과 맥락을 처음 드러내기 위한 조작은 구분한다. 최초 맥락 노출에 ‘이날 사진’ 또는 ‘정리하기’ 클릭을 요구하지 않는다.
4. 사용자는 맥락 속 다른 사진을 열거나 현재 사진 속 사람·사물 등 새로운 대상을 탭한다.
5. 새 사진을 열면 그 사진을 기준으로 맥락이 다시 구성된다. 이전 사진의 맥락이 새 사진을 설명하는 것처럼 남아서는 안 된다.

사진이 상세 화면의 중심이고 맥락은 그 아래 다음 탐색의 단서로 보인다. 별도 Organize 메뉴나 화면 진입을 요구하지 않는다. 기능명 대신 ‘이날 함께 찍은 사진’처럼 실제 내용을 드러내는 표현을 사용한다.

## 3. 맥락 후보와 에이전트의 역할

| 맥락 후보 | 함께 볼 이유 | 예시 |
|---|---|---|
| 시간·사건 | 이 사진이 속한 날이나 장면의 흐름을 이해한다 | 산책, 식당, 이후 카페의 사진 |
| 사람 | 함께 등장한 사람들과 다른 순간을 본다 | 같은 사람들이 함께 나온 다른 자리 |
| 장소 | 같은 장소에서 있었던 다른 장면을 본다 | 같은 식당의 다른 방문 사진 |
| 대상 | 대상이 등장한 다른 상황을 본다 | 같은 와인의 매장·집 식탁·모임 사진 |
| 변화·차이 | 반복된 장면이나 대상에서 달라진 것을 이해한다 | 다른 빈티지, 같은 장소의 다른 계절 |

이 다섯 가지는 후보를 관찰할 때 참고할 어휘(prior)다. 고정 분류 체계, 필수 섹션, 시나리오별 코드 분기로 사용하지 않는다. 사진에서 더 적절한 관계가 발견되면 에이전트가 새 맥락을 구성할 수 있다.

에이전트가 열린 사진과 확보된 후보를 관찰한 뒤 보여줄 관계, 제목과 설명, 사진 소속과 구성을 판단한다. 모든 사진에 같은 맥락을 붙이지 않고, 근거가 없으면 억지로 맥락을 만들지 않는다. 이름만 붙인 사진 목록으로 완료를 판단하지 않는다.

코드는 ID·접근 권한·삭제 상태·버전·날짜 처리·스키마·실행 예산 같은 결정적 조건을 검증한다. 의미 분류를 규칙으로 대신하지 않는다. 에이전트의 의미 검토 또한 사실 정확도를 보증하지 않으므로 실제 사진 검수가 필요하다.

## 4. 사실과 해석의 경계

- 촬영일은 메타데이터 근거로 확인한다. 날짜 누락·시간대 처리 정책은 후속 계약에서 명시해야 한다.
- 같은 날의 사진이라고 같은 사건은 아니다. 시간 순서는 관찰 근거이고 사건 해석은 사진을 함께 확인해야 한다.
- 함께 찍혔다고 가족·친구 관계를 확정하지 않는다. 사진이 방문·소유·구매·음용 사실을 모두 증명한다고 해석하지 않는다.
- 같은 제품 표기, 시각적 유사성, 동일한 물리적 개체를 구분한다.
- 생성 프롬프트와 평가 정답을 검색·맥락 구성 입력에 주입하지 않는다. 합성 사진의 날짜가 데모 설정이면 그 출처를 기록하고 실제 촬영 사실로 주장하지 않는다.

## 5. 이전 설계와의 차이

| 이전 방향 | 이번 결정 |
|---|---|
| 전역 Organize/Spaces 홈과 탐색 결과 Space 저장 | Space 생성·자동 게시·저장·목록·편집·쓰기 권한 모두 MVP에서 제외. 사진 상세 Organize와 내부 캐시는 유지 |
| Organize는 Connect 결과 목록의 그룹핑 | 결과 정리를 넘어, 열린 사진과 주변 맥락까지 다룸 |
| ‘이날 사진’을 제외하거나 별도 버튼으로 시작 | 관련성이 있는 그날 사진은 상세에서 자동으로 드러남 |
| Connect 결과 후보 안에서만 정리 | 사진 상세 맥락은 와인이 없는 같은 날 사진 등 기존 후보 밖의 근거도 필요할 수 있음 |
| 정해진 축이나 그룹 수로 정리 | 에이전트가 실제 근거에서 관계와 구성을 판단 |
| 연결 3회 성공을 중심으로 데모 평가 | 각 사진에서 이해한 맥락이 다음 선택으로 이어지는지도 평가 |

‘5장 미만 그룹핑 생략’, ‘그룹당 최소 2장’, ‘2~4개 그룹’은 이 UX의 확정 제품 규칙으로 채택하지 않는다. 품질·실행 예산을 위한 기술적 한도는 의미 분류 규칙과 구분해 별도 설계한다.

기존 Connect 결과를 정리할 때 검토된 후보 밖의 ID를 몰래 포함해서는 안 된다는 검증 원칙은 유지한다. 사진 상세 맥락에 필요한 추가 후보는 명시적으로 확보하고 근거를 검토해야 한다. 후보를 확보할 시점·범위·검색 예산은 아직 결정하지 않았다. 이번 UX 결정이 무제한 실시간 검색을 승인하는 것은 아니다.

## 6. 표시 시점과 계산 시점

사용자가 맥락을 만나는 시점은 사진을 열 때다. 계산까지 그때 시작할 필요는 없다. 기존 사전 분석·연결 저장을 재사용하고, 준비된 맥락을 사진과 함께 표시하는 방향으로 설계한다.

사진 기준 캐시·무효화, 미준비 자동 처리와 화면 상태는 [사진 맥락 계약](photo-context-contract.md)으로 구현했다. 탐색 경계선의 선행 준비 우선순위는 후속 과제다. 준비 실패와 확인된 맥락 없음은 구분해야 한다. 사용자가 정리 버튼을 찾아야 진행되는 구조로 돌아가지 않는다.

조회 API 속도, 사진·맥락이 실제 보이는 시간, 준비 비용과 준비율을 분리해 측정한다. 기존 loopback API 측정값을 휴대폰 체감 속도로 해석하지 않는다.

## 7. 구현 기준과 남은 설계

기존 Connect → 결과 그룹핑 데모는 재사용할 기반이다. 18장 보고서의 그룹 계약·사전 준비·PC 화면·Android 빌드 검증이 이번 사진 상세 맥락 UX까지 구현했다는 뜻은 아니다. 이 문서 작성 이후 Space 진입·자동 생성 경로 제거를 코드에 반영했다. 기존 그룹핑·사전 조회와 사진 상세 맥락 서버·Android 화면을 통합했다. 실제 사진 품질과 성능의 미달 사항은 통합 검증 기록에서 구분한다.

2026-09-08 구현 계약은 다음과 같다.

1. 선택 영역의 Connect와 열린 사진 전체의 맥락은 별도 조회·준비 단위다.
2. 현재 사진과 실제 갤러리 근거를 사용하고 들어온 연결·탐색 기록을 맥락 판단에 넣지 않는다.
3. 촬영 시각이 알려진 경우 가까운 후보를 첫 관찰 prior로 공급한다. 최종 관계는 모델이 결정하며 다른 검색으로 확장할 수 있다. 버전·모델·정책·갤러리 revision으로 캐시를 갱신한다. 선행 준비 우선순위는 남은 과제다.
4. 상세 화면에 미리보기와 준비/실패/없음을 표시하고 다음 사진·대상 선택과 뒤로 복원을 지원한다.
5. 맥락 헤더는 확보한 그룹의 전체 목록을 펼친다. 해당 사진 또는 대상을 선택하면 다음 탐색으로 이어진다.

Space 저장·사용자 쓰기 권한은 제외한다. 사진 상세 맥락은 Space 생성·저장 없이 동작한다.

도메인·API 변경은 [계약 검토 결정](context-ux-architecture.md)에 기록했다. 기존 배포 ZIP·패치는 과거 구현 산출물로 보존하며 최신 UX 반영본으로 표시하지 않는다.

## 8. 데모 수용 기준

- 와인 탭으로 관련 사진을 찾고 식당 사진을 열면, 별도 맥락 요청 클릭 없이 근거 있는 주변 사진이 보인다.
- 같은 날 맥락을 시험할 때는 실제로 확보한 날짜 근거를 사용한다. 와인이 없는 주변 장면도 정당한 후보 확보·검토를 거쳐 등장할 수 있다.
- 선택 대상이나 열린 사진이 바뀌면 결과와 맥락이 그 변화에 맞게 달라진다. 정답 ID·고정 분류로 연출하지 않는다.
- 사진·메타데이터를 직접 확인해 관계와 설명을 검수한다. 관련 사진 회수와 설명 정확도를 구분해 기록한다.
- 3hop에서는 다음 사진에 도달한 성공뿐 아니라 각 단계에서 무엇을 알게 됐고 무엇을 더 보고 싶어 선택했는지 기록한다.
- 준비됨·미준비·실패·맥락 없음의 상태와 실제 화면 대기 시간을 확인한다. 뒤로 가기는 이전 사진·선택·맥락·스크롤을 복원한다.

핵심 평가 질문: **이 맥락을 보고 무엇을 알게 됐고, 무엇을 더 보고 싶어졌는가?**

## 9. 기록의 해석

2026-09-07의 386장·Spaces 0개 handoff는 중단 시점 기록이다. 이후 참조 작업의 대화와 최종 검증 문서는 1,000장·Spaces 6개 및 실기기 확인으로 진행한 사실을 기록한다. 그 뒤 별도 합성 갤러리에서 결과 그룹핑 데모를 개발했다. 각 기록은 서로 다른 시점·범위를 나타내며 현재 DB나 main 반영 상태를 이 문서에서 새로 검증한 것은 아니다.

관련 작업: [Connected Gallery MVP 구현 계속](thread://01a07993-6c69-7340-a394-1983cd4ac1e5?hostId=local).

이 문서의 사용자 결정은 이전 자동 묶음 홈·결과 그룹핑 전용 계획과 충돌하는 제품 범위에 우선한다. 과거 보고서의 측정값과 구현 완료 기록은 해당 버전의 이력으로 보존한다.


2026-09-08 구현 계약에서는 열린 사진 전체만 맥락의 기준으로 삼고, 이전 Connect 결과·경로는 입력으로 사용하지 않는다. 후보 확보와 검토는 별도 맥락 실행에서 진행한다. 내부 캐시는 사진·모델·정책·갤러리 버전으로 무효화한다. 그룹 제목은 확보된 목록을 펼치며 새 검색을 자동 추가하지 않는다. [계약과 검토 결정](context-ux-architecture.md)을 참조한다.
