# 사진 맥락 통합의 계약 검토

2026-09-08. 기존 main의 Space 제거와 별도 개발 작업의 Connect 그룹·준비 조회·사진 맥락 구현을 대조하고 통합한다. 참조 작업의 변경 중인 파일은 수정하지 않았으며 가져온 버전을 복사본에 고정했다. 이 문서는 코드 계약 검토이며 독립 아키텍트 에이전트의 승인을 받은 것으로 표시하지 않는다.

선택 영역 기반 Connect와 사진 전체 기반 Organize는 별도 계약이다. 전자는 확보한 관련 후보를 구조화하며 추가 검색 없이 그룹을 검토한다. 후자는 열린 사진을 이해하는 데 필요한 주변 장면을 스스로 확보하고 관찰한다. 따라서 와인이 없는 사진도 실제 근거가 있으면 사진 맥락에 들어갈 수 있다. 이전 탐색 경로를 맥락 입력으로 쓰지 않아 동일 사진의 캐시와 의미가 경로에 따라 달라지는 문제를 피한다.

새 Space나 사용자 묶음 쓰기 권한은 없다. 기존 cache와 durable run을 사용하며, context 역할만 추가한다. 과거 organizer 요청의 읽기는 복구를 위해 남기고 새 실행은 계속 거절한다. Connect API는 기존 flat items와 groups를 병행해 중간·미완료 응답을 처리한다. 사진 맥락 API는 별도 summary/groups/state를 사용한다.

관계·제목·멤버는 모델이 결정한다. 코드의 그룹 최대 8개, 관찰 최대 24장, 응답·도구·시간 한도는 계산 예산이다. 최소 장수와 고정 분류를 두지 않는다. 맥락에서는 서로 다른 근거로 사진이 여러 그룹에 포함될 수 있고 각 멤버 관계를 따로 검토한다. 그룹 헤더는 확보된 그룹 목록을 펼친다. 추가 탐색은 그 안의 사진을 열거나 현재 사진의 대상을 선택해 진행한다.

캐시는 사진 버전·전체 갤러리 revision·맥락 사양·정책·모델을 포함한다. 현재 값과 관찰·검토 출처를 매 조회에서 확인한다. 모델용 짧은 ID는 전송 표현이며 저장된 실제 ID 및 검증 범위를 바꾸지 않는다. 실패를 빈 맥락이나 고정 규칙의 대체 결과로 바꾸지 않는다.

Android에서는 사진 열기와 영역 선택을 다른 화면 기록으로 다룬다. 열기는 새 사진 맥락, 선택은 Connect이며 뒤로 가기가 두 상태를 복원한다. 화면 세대가 바뀐 비동기 응답은 버리고 저장은 순서대로 수행한다. 준비 작업은 사진 전환만으로 취소하지 않아 다음 방문에서 재사용할 수 있다.

남은 위험은 실제 사진에서의 모델 완료율·관계 품질과 준비 지연이다. 사전 준비의 범위·우선순위는 구현된 조회 캐시와 별도로 평가해야 한다. UI 테스트의 합성 결과를 실제 사진 품질 근거로 사용하지 않는다. 현재 측정은 [통합 검증](context-ux-validation.md)에 기록한다.
