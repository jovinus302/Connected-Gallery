# 샘플 사진 기반 Android 실행 준비

## 구현 전 명제 (2026-09-08)

- 확정된 의도: 기존 Connected Gallery를 샘플 사진으로 사용할 수 있게 만들고 기기에서 검증한다. APK 전송은 사용자가 검증한 base64 경유 방식을 사용한다.
- AI의 해석: 기존 사진 목록 → 상세 → 대상 선택 → 관련 사진 → 맥락과 뒤로 가기 흐름을 재사용한다. 새 제품 기능은 추정해 추가하지 않는다.
- 관찰 가능한 결과: 새 APK를 빌드하고, 전송 전후 SHA-256이 일치할 때만 설치하며, 설치 결과와 앱 실행을 확인한다. 사진 경로를 확보하면 사진 연결과 탐색을 검증한다.
- 불변 조건: 원본 사진과 기존 앱 데이터를 삭제하지 않는다. 접속 키를 로그나 APK에 포함하지 않는다. 다른 worktree의 작업을 변경하지 않는다.
- 검증 계획: Android 단위 테스트와 lint, APK 빌드, 실제 에뮬레이터에서 base64 전송·해시 대조·설치·실행. 샘플 사진에서 탐색과 복원은 별도 실행 증거로 기록한다.
- 미결정 사항: 샘플 사진 위치. 현재 저장소 .runtime에 사진이 없고 emulator-5554의 MediaStore 사진 조회 결과는 0장이다. 서버 연결도 설정되지 않았다.

## 가설 리뷰

SOUND — 기존 기능을 재사용하고 설치 경로를 재현 가능하게 만든다. 사진과 서버가 없는 상태에서 탐색 품질을 입증했다고 주장하지 않는다.

## 실행 증거 (2026-09-08)

- APK 빌드: 설치된 Gradle 8.11.1로 `assembleDebug` 성공. APK 11,640,685 bytes. Wrapper 다운로드는 연결 시간 초과였고 동일 버전의 로컬 배포본을 사용했다.
- 회귀 방지: `testDebugUnitTest lintDebug` 성공. Android 테스트 XML에서 29 tests, 0 failures, 0 errors. 최초 offline lint는 캐시에 없는 의존성으로 실패했으며 정상 네트워크 실행으로 해결했다.
- 설치 안전: Python unittest 4개 통과. 바이너리 전송, 체크섬 불일치 시 설치 차단, 전송 실패 시 설치 차단, pm 실패 응답 처리와 각 경로의 임시 파일 삭제 시도를 확인했다.
- 기기 설치: emulator-5554에 새 APK를 base64 전송. SHA-256 `930b88cb68d784b375942579bdb7e8572f2c316b4614665b4f797e4e8e3da189` 일치 후 `pm install -r` 성공. `/data/local/tmp`에 이번 설치의 임시 APK가 남지 않았다.
- 실행: 패키지 실행과 프로세스 생존 확인. crash 버퍼에 항목 없음. UI에서 서버 연결 창과 갤러리 화면 확인.
- 서버 연결: 이 worktree의 가상환경에서 PC API를 `127.0.0.1:8765`로 실행했다. 인증 없는 `/assets`는 401, 인증된 `/manifest`는 200. 에뮬레이터는 ADB reverse를 통한 개발용 loopback 연결을 사용한다. 공개 HTTPS 터널 검증은 아니다. 비밀 설정은 앱 전용 저장소로 전달하고 앱이 암호화 저장 후 입력 파일을 제거했다.
- 사진 탐색: 미검증. MediaStore 사진 0장. 사용자에게 샘플 경로를 요청한 상태다. 실제 사진 분석용 선택 의존성과 모델 준비도 샘플 데이터의 준비 상태 확인 후 이어가야 한다. 서버 연결 성공을 모델 추론 성공으로 간주하지 않는다.

## 구현 리뷰

- 변경 성격: COMMITTED CHANGE (설치 자동화).
- 설치 자동화: PASS. 검증한 사용자 절차를 재사용하며 앱 제품 동작과 데이터 정책을 바꾸지 않는다.
- 전체 앱 완료 판정: INTENT GAP. 샘플 위치가 없어 사진 연결, 관련성, 자동 맥락, 연속 탐색과 복원을 실행하지 못했다. 이 기록은 전체 앱 완료를 의미하지 않는다.
