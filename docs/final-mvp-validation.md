# Connected Gallery MVP — 최종 검증

2026-09-07. 범위는 **Organize + Connect**다. Timeline/Time은 후속 CG-15로 분리했고, 앱의 Time UI와 저장된 연도 필터를 이관했다. 최종 서버는 agent spec 15다.

## 준비된 데이터와 Spaces

- 원래 Gallery **1,000장 전체 분석 완료**. 전체 이미지·설명/OCR 텍스트와 선택 영역 **4,571개**의 필수 인덱스가 모두 준비됐다. 누락·활성 중복 분석은 0장이다. 기존 분석 386장과 원래 사진 목록을 보존했다.
- 전체 사진 요약을 Organizer에 전달하고, 모델이 맥락과 후보를 제안한 뒤 별도 이미지 검증을 거쳐 **Spaces 6개·소속 사진 20장**을 저장했다. 제안 23건 중 근거가 부족한 3건을 제외했다. 총 98.65초이며 독립 검증 39.89초를 포함한다.
- Spaces는 사진 탐색의 진입점이다. 1,000장 모두에 소속을 부여했다는 뜻은 아니다. Android Spaces 탭에서 6개·20건의 캐시와 실제 소속 사진 열기를 확인했다.

근거: `resume-progress.json`, `final-spaces-validation.json`, `device-spaces-validation.json`.

## 실제 Android 탐색

SM-S918N / Android 16에서 **사람 → 사물 → 장소**로 연속 3hop을 수행했다. 매 단계에서 앞선 결과 사진을 열고 새 대상을 탭했다. 중간 APK 설치·서버 재시작·요청 실패 없이 세 단계 모두 독립 검증된 결과를 표시했다.

| 단계 | 결과 | 서버 첫 결과 | Android 결과 콜백 |
|---|---:|---:|---:|
| 사람 | 4장 | 35.46초 | 36.308초 |
| 사물 | 5장 | 21.45초 | 22.544초 |
| 장소 | 3장 | 23.53초 | 24.246초 |

이 기록은 spec 14의 동일 Connect 경로에서 측정했다. 이후 spec 15는 Spaces 저장 전 검증을 추가했다. 콜백 시간은 화면의 실제 픽셀 렌더링 지연을 별도로 측정한 값이 아니다.

Related 실행 중 Same moment로 바꿨을 때 이전 요청이 취소됐고, 취소된 결과 이벤트는 0건이었다. Same moment 결과 2장이 앱에 표시됐다. 다른 사진을 열었다가 돌아오면 사진·선택 조건·결과와 스크롤 위치 `[0, 176]`이 복원됐다. USB reverse 연결을 끊고 앱을 재실행해도 저장된 사진과 결과를 볼 수 있었고, 연결 복구 뒤 1,000장 준비 상태와 이전 화면이 유지됐다.

근거: `device-three-hop-validation.json`, `device-modifier-validation.json`, `device-back-scroll-validation.json`, `device-reconnect-validation.json`.

## 품질·안정성 변경

탐지/OCR 픽셀 좌표를 실제 입력 크기와 crop 위치로 변환해 선택 영역을 전체 사진 좌표로 반환한다. 늦게 도착한 분석을 제스처가 읽지 못하던 Android 문제를 수정했다. 선택 영역도 자동 인덱싱하며, 한 사진의 여러 영역이 검색 후보 수를 소진하지 않도록 사진별 최고 점수를 먼저 고른다.

Connect와 Spaces는 후보 제안의 주장·전체 사진 설명을 그대로 믿지 않고 별도 문맥에서 실제 이미지를 대조한다. 부분 결과 뒤 일반 답변으로 끝나는 경로도 검증을 거친다. 후보 번호 누락·중복은 같은 이미지로 한 번만 형식 수정을 요청하며, 계속 잘못되면 미검증 결과를 게시하지 않는다. 사용자 명시적 Space 편집은 보존한다. 의미 판단·맥락 생성은 모델이 수행하며 고정 의미 분류나 키워드 규칙으로 대체하지 않았다.

전체 인덱스 API 표본 6건(사람·사물·모빌·텍스트·장소·Same moment)은 spec 12에서 모두 완료됐고, 검증 후 결과는 5/3/3/2/1/3장이었다. 완료 시간은 18.19~55.42초였다. 이전 제공자 시간 초과, 잘못된 후보, 판정 형식 오류와 부분 결과 우회 사례도 별도 기록에 남겼다. 성공 사례만 모아 전체 실패율로 표현하지 않는다.

## 자동 검증과 한계

- 최종 서버 테스트 **63개 통과**. 인덱스 원자적 저장·복구, 좌표, 중복 후보, 검증 전 비노출, 부분 결과, 형식 수정 상한, 취소, Spaces 소속과 사용자 편집 보존을 포함한다.
- Android assembleDebug·단위 테스트·lintDebug 통과. 맞춤 이미지 탭, 확대 후 길게 누르기, 늦게 도착한 분석/콜백의 실기기 회귀 테스트 **3개 통과**. 최종 Android 소스의 APK가 기기에 설치돼 있다.
- 최초 결과 5초·최종 15초 속도 목표는 **미달**이다. 전체 사용자 대상 P@5·p95, Find 성공시간, 재사용 의향은 **미측정**이다. 이 작업의 자동 조작을 사용자 참여 평가로 간주하지 않는다. 완벽한 인물 ID는 범위 밖이다.
- 기존 선택 영역 전체를 재검증·수정한 것은 아니다. 잘못된 crop이나 불충분한 증거에서는 빈 결과·부분 결과·재선택 안내가 나올 수 있으며, 제공자 장애도 가능하다.

사진·실행 ID·OCR·개인별 판정 근거와 키는 공개 보고에서 제외했다. 실행 DB와 사진은 로컬 `.runtime/`, 검증 중간 자료는 Git에서 제외된 `work/`에 남는다. PC 서버는 loopback 8765에서 실행하며 휴대폰은 USB reverse로 연결한다.
