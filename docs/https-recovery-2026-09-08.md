# HTTPS 연결 복구 (2026-09-08)

자동 맥락 구현 배포 직후 HTTPS 확인이 300초 동안 통과하지 못해 시작 도구가 터널을 종료했다. 당시에는 HTTP 실패 상태와 전송 예외를 기록하지 않아 최초 실패의 근본 원인을 확정할 수 없다. Cloudflare 측 터널 등록 자체는 성공했었다.

`scripts/start-pc-server.py`에 HTTPS 준비 확인 로그를 추가했다. HTTP 상태, Cloudflare 요청 식별자·오류 번호, DNS/TLS/연결 예외 종류를 터널별 `-probe.jsonl`에 남긴다. 인증 정보와 갤러리 응답 본문은 기록하지 않는다.

명시적으로 승인받은 공개 HTTPS 연결 재실행에서 Windows 주소 조회가 `ConnectError: [Errno 11001] getaddrinfo failed`로 약 18초간 실패했다. 이후 같은 터널 주소가 HTTP 200으로 응답했다. 이번 시도의 지연 원인은 새 주소의 DNS 해석 준비 지연이며, 과거 300초 실패까지 같은 원인이었다고 단정하지 않는다. 시스템 DNS·인증서 검증·서버 인증 설정은 변경하지 않았다.

복구 후 PC와 연결된 Galaxy S23 Ultra 양쪽에서 HTTPS 인증 health 요청 200, 비인증 assets 요청 401을 확인했다. 휴대폰은 curl의 인증서 검증을 활성화한 상태에서 직접 HTTPS로 확인했으며 USB reverse를 통과한 결과가 아니다. 새 연결 정보는 앱 전용 저장소에 전달했고 USB reverse는 제거했다. 다음 앱 실행 시 기존 debug provisioning 경로가 설정을 가져온다. 앱 자동 실행이나 추가 사진 모델 작업은 수행하지 않았다.

진단 로그 테스트 3개가 통과했다. Cloudflare 오류 파싱, 연결 예외와 인증 정보 제거, 성공 응답의 본문 미기록을 검증한다. 갤러리 접근에는 인증이 계속 필요하고, 임시 HTTPS 주소는 PC와 터널 프로세스가 실행되는 동안 사용할 수 있다.
