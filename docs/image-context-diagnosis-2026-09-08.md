# 실기기 이미지·맥락 실패 진단

2026-09-08. Galaxy S23 Ultra에서 파스타 사진을 열었을 때 “주변 사진의 맥락을 정리하지 못했어요”가 표시되는 문제를 조사했다. 네트워크 오류, 이미지 전달 실패, 모델의 결과 구성 실패를 구분했다.

## 확인한 원인

ADB `device`, USB 디버깅 활성화, shell·앱 run-as 접근이 정상이다. PC와 휴대폰 모두 HTTPS 인증 health 요청 200, 비인증 assets 요청 401을 확인했다.

이미지 분석 경로 전체가 동작하지 않는 상태는 아니었다. 저장된 파스타 사진 분석은 파란 접시·파스타·생선 등 실제 화면과 대응했다. 분석 레코드 1,000개가 서로 다른 것은 확인했지만 전체 정확도를 판정한 것은 아니다. 임의 숫자·색·도형만 넣은 합성 이미지로 실제 Proxy를 호출했을 때, source HumanMessage와 candidate ToolMessage 안의 이미지 모두 숫자와 색을 정확히 읽었다. 이전에 승인한 와인·파스타 사진 두 장도 분석 설명 없이 전달했을 때 각각의 실제 장면을 구분했다.

SDK HTTP JSON을 모의 전송으로 검사해 이미지 bytes, 크기·색, 바로 앞 사진 ID, 도구 결과 중첩, 별칭 복원을 확인했다. 이 경로에서 이미지 누락이나 코드에 의한 ID 뒤섞임은 발견하지 못했다. 원격 Proxy 내부 구현이나 모든 사진의 인식 품질까지 보증하는 검사는 아니다.

실패 기록에서는 계획한 관찰을 끝내기 전에 제출하거나, 관찰하지 않은 사진을 그룹에 넣는 문제가 반복됐다. 마지막 일반 응답에서 모델이 `complete=false`를 제출하면 남아 있던 마지막 수정 응답을 쓰지 않고 종료했다. 관찰한 ID를 설명문으로만 제공하던 계약도 모델의 잘못된 멤버 선택을 충분히 예방하지 못했다.

별도로 검토 모델이 그룹 설명의 동일 장소 주장을 요약에 전가하는 사례가 있었다. 요약에는 같은 자리로 단정하지 않는다고 적혀 있었지만, 검토는 그 반대로 요약을 해석했다. 기존 `summary_supported=false`에는 요약 자체의 인용이 필요하지 않았다. 이는 이미지 미전달과 다른 실패 경로다.

## 수정

- 각 응답에 실제 관찰한 다른 사진과 아직 확인하지 않은 계획상의 사진을 제공한다.
- 제출 도구의 사진 ID enum은 실제 전체 이미지를 확인한 다른 사진으로 구성한다. 원본·미관찰 사진·부분 영역만 본 사진은 enum에 들어가지 않는다. 스키마에도 메시지와 동일한 사진 ID 별칭을 적용한다.
- 미완료 제출에는 기존 8응답·도구 예산 안에서 한 번의 수정 기회를 제공한다. 모델이 다시 미완료를 선택하면 그대로 존중하며 코드가 완성 상태를 바꾸지 않는다.
- 요약 거절은 요약 자체의 실제 인용을 요구한다. 다른 필드의 문구·빈 인용을 거부하고 부정·한정 표현을 포함한 절을 검토하도록 지시한다. 부분 문자열 검사만으로 의미 오독을 완전히 방지할 수 있다는 주장은 하지 않는다.
- 독립 이미지 검토와 별도 문구 검토, 사진별 버전·갤러리 revision 검증은 유지한다. Context spec은 8, 정책은 `photo-context-v8-grounded-submission-review`로 변경해 과거 정책 결과를 재사용하지 않는다.

## 검증 결과와 범위

최종 서버 테스트 350개 통과. Android 코드·APK는 변경하지 않았다. 실제 설치된 앱에서 서버 요청·준비 상태·결과 표시를 확인했다. 중간 수정(v6)은 48.01초에 2그룹·8장, 최종 수정(v8)은 48.57초에 1그룹·6장을 반환했다. v8에는 멤버 제출 검증 오류가 없었고 독립 이미지·문구 검토를 통과했다. 원본과 최종 6장 전체를 직접 보고 식사 테이블의 여러 장면과 설명의 대응을 검수했다. 실제 결과의 그룹 펼치기·돌아가기도 확인했다. v7에서는 멤버 오류가 없어졌지만 요약 검토 문제로 실패했으므로 성공 기록에 포함하지 않는다.

실기기 의미 검증은 원본과 분리한 갤러리 복사본을 사용했고, 마지막 실행은 이미 승인한 사진 목록 안으로 이미지 관찰을 제한했다. 원본 서버에서 다양한 사진의 일반 성공률, 실제 사진 연쇄 3hop, 준비되지 않은 첫 결과 지연 목표는 이 검사로 완료 판정하지 않는다. 48.57초는 요청부터 서버 결과 완료까지이며 전체 휴대폰 렌더링 시간은 아니다.

검증 초기 앱 재연결의 자동 동기화가 별도 analyst 작업을 시작해 기존 검증 승인 목록 밖의 사진 두 장을 기존 Proxy로 전달한 사실을 확인했다. 이 작업은 중지했으며 이후 검증 서버에 쓰기 요청 차단(승인된 맥락 prepare만 허용)과 공통 이미지 전달 단계의 승인 ID 검사를 함께 적용했다. 개인 사진·모델 원문·연결 토큰은 레포에 포함하지 않는다. 이 사건을 승인 범위 내 시험으로 계산하지 않는다.

합성 이미지로 외부 모델 전달을 다시 확인하려면 기존 `.env`가 준비된 레포에서 `python scripts/probe-vision-transport.py`를 실행한다. 이 명령은 임의 숫자와 도형의 합성 이미지 두 장만 사용하며 기존 Proxy에 모델 요청을 보낸다. 결과는 `.runtime/diagnostics/vision-transport.json`에 저장된다.
