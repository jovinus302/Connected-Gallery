# 사진 상세 맥락 계약

2026-09-08 · 실기기 수정 통합 v9 구현 계약. 실제 준비율·사진 의미 검수는 해당 버전의 별도 보고서를 따른다. [기존 v3 PC 데모](pc-demo-completion.md), [첫 통합 검증](demo-main-integration.md), [실기기 이미지·맥락 진단](image-context-diagnosis-2026-09-08.md)을 구분한다.

사진 상세 맥락은 사용자가 연 **사진 전체**를 기준으로 생성한다. 선택 영역의 Connect 결과와 별도 단위다. 이전 연결, 탐색 이력, Space, 생성 프롬프트 또는 평가 정답은 맥락 입력으로 사용하지 않는다. 같은 사진의 맥락은 어느 경로로 열었는지에 따라 달라지지 않는다.

## 조회와 준비

`GET /assets/{photo_id}/context`는 읽기 전용이다. 응답은 `photo_id`, `revision`, `state`, `capture`, `context`를 포함한다. `state`는 `ready`, `empty`, `pending`, `running`, `failed` 중 하나다. `running`에는 `run_id`, `failed`에는 통제된 오류 코드 `context_preparation_failed`가 추가된다.

`context`가 존재하면 `summary`와 `groups`를 포함한다. 각 그룹은 `id`, `title`, `reason`, `photo_ids`를 가진다. 맥락이 없는 것으로 확인된 `empty`도 근거를 설명하는 `summary`와 빈 그룹을 반환한다. 준비 실패를 빈 맥락으로 표시하지 않는다. 조회는 모델, 작업, 이벤트, 캐시 쓰기를 시작하지 않는다.

`POST /assets/{photo_id}/context/prepare`는 동일 사진·동일 갤러리 스냅숏의 진행 중 작업을 재사용한다. 응답은 조회 응답에 `run_id`와 기존 실행 상태 `status`를 더한다. 이미 준비된 맥락은 작업을 추가하지 않는다. 실시간 모드에서는 화면이 미준비 상태를 관찰해 자동 요청할 수 있다. 준비 결과 조회 전용 데모에서는 이 POST를 쿠키와 Bearer 양쪽 모두 거부한다.

오프라인 준비는 `RunService.start(RunRequest(role="context", photo_ids=[photo_id]))`를 사용한다. 일반 작업 테이블에 남기며, 취소·시간 초과·재시작 복구를 지원한다. 재시작에서는 같은 스냅숏 작업을 처음부터 다시 실행하며, 다른 모델·갤러리·정책의 오래된 작업은 취소한다. 중간 대화 내용을 다시 사용하는 체크포인트는 없다.

## 후보 확보와 의미 판단

원본 전체 이미지와 최대 40장의 메타데이터·기존 분석 발췌를 명시적 초기 후보 공급으로 보낸다. 알려진 촬영 시각이 있으면 원본과 가까운 시각의 후보를 먼저 공급하고, 시각이 없으면 기본 목록 순서를 사용한다. 이는 관찰을 시작할 prior이며 관계·같은 날·사건 그룹의 근거가 아니다. 에이전트는 `plan_photo_context`로 사진 전체에서 관찰한 사실, 이 사진을 이해하는 데 필요한 질문, 추가로 확인할 근거와 후보를 먼저 명시한다. 질문이나 후보를 시간·사람·장소 등의 고정 축으로 강제하지 않는다. 사진에 의미 있는 주변 장면이 있는데 가장 큰 사물만 찾는 검색으로 축소하지 않도록, 독립 검토에서 계획의 범위와 실제 추가 관찰의 충족 여부도 판단한다. 한 가지 관계만 의미 있는 사진에 억지로 다른 분류를 붙이지 않는다. 에이전트는 검색 도구, 조회 조건, 추가 관찰, 보여줄 관계, 제목·설명과 멤버를 선택한다. 초기 목록에 없는 후보도 시각·텍스트·얼굴·위치·시간 검색으로 명시적으로 확보할 수 있다. 모든 검색 결과 ID는 현재 갤러리 접근 범위 안으로 제한한다.

제출한 각 멤버는 실제 **전체 사진**을 관찰해야 한다. 작은 영역만 본 것으로 전체 사진을 관찰했다고 처리하지 않는다. 에이전트와 별개의 새 메시지 문맥에서 원본·멤버 전체 이미지와 날짜 출처를 다시 제공하고, 요약 및 모든 그룹 제목·설명의 주장을 멤버별로 검토한다. 이전 분석·제안자의 설명은 독립 검토의 이미지 근거로 사용하지 않는다. 검토되지 않은 멤버, 누락·중복 검토, 모순 또는 불확실한 주장이 남으면 완료하지 않는다. 원래 실행 예산 안에서 한 번 수정하고 다시 검토할 수 있다. 모델 검토가 사실 정확도를 보증하지 않으므로 실제 사진 검수는 별도로 한다.

v3에서 도입한 계획 검증을 유지한다. 에이전트가 직접 계획에 지정한 모든 후보도 전체 사진을 관찰해야 완료를 제출할 수 있다. `plan_photo_context`는 질문과 계획을 기록하고, 에이전트가 직접 지정한 확보된 후보 중 아직 전체 이미지를 보지 않은 사진을 해당 도구 호출에서 읽어 실제 이미지 블록으로 반환한다. 호스트가 후보를 추천하거나 추가하지 않는다. 에이전트는 반환된 이미지를 읽고 관계를 판단한다. 이미 전체 이미지를 본 후보는 다시 읽지 않으며 새 이미지가 없으면 현재 계획·관찰 메타데이터만 반환한다.

이미지 읽기 전에 전체 후보의 접근·버전·원본 제외와 누적 24장 예산을 검사한다. 읽기 도중 일부 사진에서 오류가 나면 앞서 성공한 실제 이미지와 남은 후보·통제된 오류 코드를 함께 반환한다. 이미지와 현재 메타데이터를 반환할 수 없는 후보를 `full_seen`으로 인정하지 않는다. 계획은 미해결 후보를 유지하므로 실패를 관찰 완료로 바꾸지 않는다. 에이전트가 다시 관찰을 요청하거나 관찰하지 않은 후보를 계획에서 제외할 때는 `plan_photo_context`를 다시 호출하고, 제외에는 `revision_reason`을 명시한다. 기존 18도구·계획 응답·전체 시간 예산을 늘리지 않는다. 코드는 명시된 작업의 이행 여부를 검증하며, 제외된 사진이 의미적으로 무관하다고 대신 판단하지 않는다. 어느 사진이든 반드시 비슷한 사물 밖의 멤버나 특정 분류를 포함해야 한다는 규칙은 없다.

최종 문구는 기존 구성·시각 검토와 별개의 `gpt-5.4-mini` 검토를 받는다. 이는 기존 연결의 논리 모델 선택이며 새 제공자 계정을 연결하지 않는다. 기본 구성 모델의 변경 없이 이 문구 검토 모델을 따로 지정한다. 원본과 최종 멤버의 실제 전체 이미지, 날짜 출처, 정확한 최종 문구만 제공한다. 확인된 빈 맥락에서는 부재 주장의 검토를 위해 전체 관찰 후보도 제공한다. `/summary`와 모든 `/groups/{index}/title`, `/groups/{index}/reason`을 각각 정확히 한 번 검토해야 하며, 실패한 항목의 인용은 해당 문구에 실제 존재해야 한다.

문구 검토는 자연스럽게 읽히는지와 실제로 주장한 범위의 근거를 구분한다. 동일 라벨·설정된 같은 날짜·비슷한 장면이라는 제한된 주장을 같은 물리적 병이나 같은 실제 사건의 주장으로 강화해서 거부하지 않도록 지시한다. 반대로 뒤쪽 문장에 새로 나온 동일 병·다른 병·실제 촬영 등의 주장은 앞쪽 단서나 단서 문구로 정당화되지 않는다. 시각 검토와 문구 검토는 같은 의미 검토 라운드에서 병렬로 실행하고 피드백을 합친다. 두 단계가 모두 통과해야 완료되며, 전체 의미 수정은 기존과 같이 한 번만 허용한다.

모든 경로·횟수·스키마가 정확하고 모델이 해당 필드를 명시적으로 불합격 판정했지만 인용만 생략했다면, 어댑터가 그 필드의 원문 전체를 그대로 붙여 기존 의미 수정 단계로 전달한다. 불합격 판정과 모델의 사유는 유지한다. 모델이 부분 인용을 제공한 것으로 표시하지 않도록 피드백의 `adapter_quote_provenance`와 `context_wording_normalized` 이벤트에 `full_field_fallback` 경로·개수를 기록한다. 누락·중복·외부 경로 또는 제공된 인용이 원문과 다른 오류는 계속 치명적 형식 실패다. 이 처리는 추가 모델 호출·검토 라운드·성공 기준을 만들지 않는다.

아래 한도는 계산 예산이며 분류 규칙이 아니다.

- 계획 응답 7회, 후보 도구 호출 18회. 초기 목록 조회도 1회로 계산한다. 제출 형식 문제로 결과를 확정하지 못하면 제출만 가능한 응답·도구 호출 각 1회를 추가로 허용한다. 이때 새 후보 확보·관찰은 금지하며 원래 전체 시간 예산과 독립 의미 검토를 유지한다.
- 목록에서 확보하는 서로 다른 사진은 최대 100장. 추가 검색의 각 응답도 최대 100개다.
- 원본 외에 관찰하는 서로 다른 사진은 최대 24장. 그룹 멤버 항목 전체도 최대 24개다. 한 사진을 서로 다른 관계에 포함할 수 있지만 각 관계를 별도로 검토한다.
- 그룹은 최대 8개이며 고정 분류, 필수 섹션, 최소 장수는 없다. 요약은 1~2개의 짧은 문장·최대 250자, 각 그룹 제목은 최대 80자, 설명은 최대 240자다. 이는 상세 화면의 읽기 부담을 줄이는 맥락 전용 제한이며 Connect 그룹 계약을 바꾸지 않는다.
- 실행 전체 기본 제한은 300초. `CG_CONTEXT_TIMEOUT_SECONDS`로 60~600초 범위에서 변경한다. 독립 시각 검토의 형식 수정은 검토 시도마다 한 번, 의미 수정은 전체 한 번이다.
- 문구 검토는 라운드당 한 번, 최대 45초이며 기본 모델 재시도·fallback을 사용하지 않는다. 최대 두 의미 검토 라운드 안에 포함되고 전체 300초 제한을 늘리지 않는다. 각 문구 경로의 검토가 누락·중복되면 준비 완료로 게시하지 않는다.

큰 갤러리의 비어 있지 않은 준비 맥락은 관찰한 관계를 확인한 제한된 뷰이며 전체 관계를 찾았다는 뜻이 아니다. `empty`는 갤러리의 모든 후보 전체 이미지를 관찰하고 독립 검토에서도 유용한 관계가 없다고 확인했을 때만 허용한다. 이 범위를 실행 예산 안에서 확인할 수 없다면 실패·미완료이며, 빈 인덱스로 맥락 없음을 선언하지 않는다.

## 날짜

`captured_at`이 없거나 시간대가 없거나 `time_source`가 `unknown`·`modified`이면 날짜 맥락 근거에서 제외한다. `exif`·`media_store`는 출처를 유지한다. `demo_fixture`는 `device_id="synthetic-demo"`이고 시간대가 명시된 날짜만 허용한다. 이는 데모 설정이며 실제 촬영 사실이 아니다.

현대 날짜를 사용하는 이번 데모의 일자 비교는 Asia/Seoul의 UTC+09:00으로 정규화한다. `capture`는 원래 ISO 값 `value`, `source`, `timezone="Asia/Seoul"`, 정규화한 `date`를 반환한다. 설정 날짜를 사용한 맥락 설명에는 `데모 설정 날짜`를 명시하며 날짜가 **설정되었다**고 표현한다. 실제로 몇 분 간격으로 촬영했다는 주장으로 바꾸지 않는다. 날짜 일치만으로 같은 사건을 주장하지 않는다. 흔한 나무 테이블·의자·액자·벽색이 비슷하다는 이유로 같은 실내 공간이나 같은 식사 자리를 주장하지 않으며, ‘가능성이 높다’ 등의 수식어만 붙여 근거 부족을 해소했다고 보지 않는다. 실제로 일치하는 특징적인 공간 구조와 세부가 없다면 관찰한 공통 특징을 설명한다. 역사적 시간대 변경을 포함하는 날짜 지원은 이 계약에 포함하지 않는다.

## 내부 저장과 무효화

기존 `cache(key, revision, data)`를 재사용하고 사용자 Space를 생성하거나 읽지 않는다. 현재 맥락 사양은 **v6**, 정책은 `photo-context-v6-source-prior-plan-and-wording-review`다. v3의 계획·독립 문구 검토와 main v5의 시각 근접 후보 공급·전송 ID 처리를 통합했다. 키는 사진 맥락의 독립 사양·정책·구성 모델·문구 검토 모델·원본 ID·원본 버전·갤러리 revision을 포함한다. 이전 v1~v5 캐시를 삭제하지 않으며 새 키가 과거 값을 준비된 결과로 사용하지 않는다. 기존 Connect 사양을 이 기능 추가만으로 변경하지 않는다.

캐시 문서는 `kind="photo_context"`, `photo_id`, `context_spec`, `context_policy`, `context`, `evidence`를 갖는다. `evidence`에는 당시 revision, 원본 버전, 전체 이미지로 관찰한 ID, 그 사진들의 버전, 정확한 `(group_id, photo_id)` 검토 목록, 요약 검토 여부를 남긴다. 조회는 현재 원본·멤버·관찰한 사진의 존재와 버전, revision, 검토 목록과 그룹의 일치, 멤버의 관찰 여부를 다시 검사한다. 무효하거나 손상된 문서는 준비된 맥락으로 표시하지 않는다. 실행 이력을 제외한 배포 데이터도 이 최소 관찰·검토 출처를 보존한다.

v3에서 추가한 증거를 유지한다. 최종 `planned_photo_ids`, `wording_review_model`, `wording_reviewed`, `wording_checked_paths`도 포함한다. 계획 후보가 실제 관찰에 포함되는지, 문구 검토 모델이 현재 선택과 일치하는지, 최종 요약·제목·설명의 모든 경로를 정확히 검토했는지도 읽기 시점에 확인한다.

## 모델 전송 ID

32자를 넘는 사진 ID는 모델 전송 경계에서만 짧은 불투명 ID로 표시하고, 모델의 도구 응답을 실제 ID로 되돌린 뒤 기존 검증을 실행한다. 원본·캐시·API·Android의 ID를 바꾸거나 결과 멤버를 자동 추가·삭제하지 않는다. 이미지 바이트는 변환하지 않는다. 각 비동기 실행의 매핑은 분리한다. 제출 검증 실패에는 모델이 복사할 수 있는 정확한 관찰 완료 ID와 아직 관찰이 필요한 계획 ID를 돌려준다. 이는 형식 복구이며 의미 판단이나 근거 검토를 대신하지 않는다.

## Android 상세 화면

사진을 열 때 이전 선택 영역과 결과를 새 사진에 상속하지 않는다. 사진 전체의 맥락을 자동 조회하고 `pending`이면 준비를 요청한다. 이미 실행 중이면 조회만 반복하며, 준비된 결과와 확인된 빈 맥락은 새 모델 작업을 만들지 않는다. 실패는 사용자가 재시도하기 전 자동으로 반복하지 않는다. 같은 revision에서 준비 시작을 반복하는 루프도 차단한다.

맥락 제목·설명과 사진 미리보기가 사진 아래에 표시된다. 날짜는 출처가 있는 촬영 메타데이터로 따로 표시한다. 그룹 제목은 이미 확보한 그룹의 전체 목록을 펼친다. 사진을 누르면 그 사진의 자동 맥락으로, 사진 속 대상을 누르면 선택 영역의 Connect 결과로 이동한다. 별도 ‘이날 사진’·정리 버튼이나 Space 저장은 없다.

뒤로 가기는 사진·선택·결과·그룹 전체 보기·세로 위치·가로 사진 인덱스를 복원한다. 저장 쓰기는 순서대로 처리하고 오래된 화면의 응답은 적용하지 않는다. 맥락은 열기·뒤로 가기·동기화 후 서버에서 다시 확인하며, 확인 중 임시 화면의 위치로 저장된 스크롤을 덮어쓰지 않는다. 앱 재시작과 과거 기록도 이 경로로 복원한다. 확대 배율과 가로 행의 픽셀 단위 오프셋은 저장하지 않는다.

통합 소스에서 이전 계약의 캐시는 준비된 v6 결과로 승격하지 않는다. 기존 전달 데모는 같은 버전의 소스·데이터 ZIP 조합으로 재현한다. 이 머지에서 유료 모델 재준비를 자동 실행하거나 기존 실행 데이터·사진을 수정하지 않았다.
