# Connected Gallery — 한 장이 다음 장면을 여는 순간

시나리오·콘티 v1 · 2026-09-10 · **EXPERIMENT / 제작 전 기획안**

**제안: 54초, 1920×1080, 24fps, 내레이션 없이 사진·행동·짧은 문구로 전달하는 본편.** 따뜻한 사진 아틀리에와 기존 세 캐릭터, 본편 사진 6장을 사용한다. 러닝타임과 내레이션은 승인된 요구가 아니라 이번 편집 가설이다. 모델링·이미지 생성·애니메이션·렌더링은 시작하지 않았다. 이 문서는 원본 저장소 밖에 작성했다.

## 1. 기획 의도와 감정 곡선

**사진 속 와인 라벨 하나를 선택한 사람이, Agent들의 관찰과 근거에 따른 수정 과정을 거쳐 식당을 발견하고, 그 사진에서 새로 궁금해진 사람을 따라 바닷가의 다른 순간까지 도착한다.**

감정은 ‘알아보고 싶은 단서’에서 출발해, ‘아직 맞지 않는다’는 짧은 멈춤, ‘찾았다’는 첫 보상, ‘이 사진도 함께 볼 이유가 있네’라는 이해, ‘다음에는 이 사람’이라는 새 호기심, 바다가 열리는 여유로 흐른다. 실패 장면은 Agent가 우왕좌왕하는 코미디가 아니라, 주장을 고쳐 더 정확히 보는 순간이다.

| 구간 | 감정 | 화면에서 감정이 바뀌는 원인 |
|---|---|---|
| 0–3초 | 궁금함 | 이름을 입력하는 대신 눈앞의 붉은 원 라벨을 선택한다. |
| 3–8초 | 기대 | 요청이 나갔다 돌아오고, 표식이 사진으로 열린다. |
| 8–14초 | 짧은 의심 → 납득 | 사진은 찾았지만 선택한 라벨의 근거가 없다. 원본의 구체적인 단서가 다음 요청에 남는다. |
| 14–23초 | 첫 발견 | 식당과 매장 사진에서 비교할 라벨이 보인다. 근거 확인 뒤 결과가 정리된다. |
| 23–33초 | 이해의 확장 | 식당을 열자 사진 전체가 기준이 된다. 앞서 물러났던 거리·카페가 설정 날짜라는 다른 이유로 돌아온다. |
| 33–43초 | 새 호기심 → 뜻밖의 장면 | 사용자가 사람을 새로 선택한다. 확인·정리를 거쳐 바닷가 사진이 크게 열린다. |
| 43–50초 | 발견의 여운 | 바닷가의 사람과 주변 풍경을 보고, 다른 날의 식당·거리 사진을 새 기준 아래 함께 본다. |
| 50–54초 | 연결된 경험을 기억 | 실제 지나온 경로와 제품명, 카피, 제작 크레딧이 남는다. |

### 확정 요구, 해석, 불변 조건

확정 요구는 행동하는 Agent, 사진의 연결과 연속 탐색, 빠르고 명확한 컷, 기존 자산과 승인 콘셉트의 존중, 무료 제작 도구, 마지막 Astra 제작 크레딧이다. 현재 단계의 산출물은 검토 가능한 시나리오와 콘티다.

이번 해석은 **54초 / 무내레이션 / 하나의 따뜻한 작업 공간 / 본편 6장 / 확장 사례는 별도 영상**이다. Agent들의 내부 사고 대신 선택·요청·반환·관찰·제출·검토라는 외부 행동을 안무로 옮긴다. 조명과 음악이 고조되어도 성공률이나 처리 속도를 주장하지 않는다.

보존할 조건은 다음과 같다.

- 첫 Connect의 기준은 끝까지 ID 0에서 선택한 와인이다. 첫 검토는 ID 4·3 모두 미지원이며, 정해진 조건에서 한 번만 재탐색한다.
- 목록 반환, 전체 이미지 관찰, 독립 검토, 검토된 결과를 서로 다른 상태로 보여준다.
- 결과 정리에는 ID 1·2만 들어간다. ID 0은 출발점으로 남고 새 발견으로 중복 집계되지 않는다.
- ID 1을 열면 별도의 사진 전체 맥락 작업을 시작한다. ID 3·4는 이 작업에서 다시 확보·관찰·검토한다. 앞선 탈락이나 탐색 이력 자체를 맥락의 근거로 쓰지 않는다.
- 사람 Connect는 사용자의 새 선택으로 시작한다. 그 결과에 기준 사진 ID 1을 새로 찾은 사진으로 중복 넣지 않는다.
- ID 5를 열면 그 사진 전체를 기준으로 맥락을 다시 준비한다. ID 1·3의 예전 통과 표시를 새 작업의 검토로 대신하지 않는다.
- 날짜는 가상 설정이며, 라벨 유사성은 같은 물리적 병·구매·소유·방문 사실을 뜻하지 않는다. 인물의 개인적 관계와 장소 이름을 만들지 않는다.

### 구현 전 가설 리뷰: SOUND

관찰 가능한 관계 변화가 이미 발표에 있고, 세 캐릭터의 역할과 조건부 귀환은 기존 시연·코드에 있다. 이번 안은 이 두 강점을 한 시간선에 연결한다. 새 제품 정책이나 추가 사진을 전제로 하지 않고, 컷 길이·구도·카피만으로 수정 가능한 작은 실험이다.

45초를 그대로 유지하는 대안은 검토와 후반 맥락 작업을 더 압축해야 한다. 본안은 재검색·확인 구간에 4초, 사람 탐색·결과 열기에 4초, 바닷가 맥락에 3초를 더 주고, 시작과 식당 열기에서 합계 2초를 줄여 **순증 9초**로 잡았다. 긴 전환으로 늘리는 시간이 아니다. 35초 이하나 15초 버전은 이 본편의 대체안으로 삼지 않는다. 핵심 과정을 뺀 별도 티저라면 다른 목적의 작업이다.

**가설 변경 이력 · 2026-09-10:** 최초 작성 중에는 52초를 제안했다. 문서 자체 점검에서 사람 후보의 비교·정리·관계 검토를 같은 짧은 숏에 몰아넣는 위험을 발견했다. 정리·관계 확인을 별도 1.5초 숏으로 나누고 바닷가 열기의 안정 판독에 0.5초를 더해 54초로 개정했다. 기존 52초의 가설은 이 이력에 보존한다. 관찰 결과나 불변 조건을 약화하는 변경은 아니다.

성공 가설은 ‘짧은 반복 안무를 익힌 관객이 후반에도 처리 순서와 기준의 변화를 따라간다’이다. 이를 정지 콘티 검수, 무음 연속 재생, 실제 출력의 단서 판독으로 나누어 확인한다. **SOUND는 촬영·편집할 이유가 타당하다는 판단이며, 영상 완성도나 관객 이해도의 PASS가 아니다.**

## 2. 기존 자료 소급 검토

이 절은 **현재 홍보 목적에서 수행한 소급 검토**다. 과거 구현자가 처음부터 이번 해석을 가졌다고 보지 않는다. 초기 명제, 시네마틱 개정, embodied 개정은 각각 당시의 승인과 해석을 기록한다. 그 기록을 이번 문서로 대체하지 않는다.

근거 표기의 R은 아래 자료 목록, U는 이번 직접 화면 관찰이다.

| 항목 | 확인된 사실·잘된 점 | 이번 해석·부족한 점 | 이번 기획에서 고칠 점 | 근거 |
|---|---|---|---|---|
| 제품 이야기 | 발표는 같은 6장으로 와인 → 식당 → 사람 → 바닷가를 연결한다. 열린 사진 아래 맥락도 바뀐다. | 사진 수보다 **역할과 기준의 변화**가 발견의 보상을 만든다. | 결과 정리 이후 약 절반을 맥락과 다음 탐색에 배정한다. | R1·R2·R3, U1–U3 |

| 확장 자산 | 5장에 안내문 3페이지, 인형 3장, 카페 계절 3장이 있다. | 본편에 모두 넣으면 관계가 바뀌는 와인 이야기의 집중이 흐려질 수 있다. | 본편은 6장으로 끝내고 확장 예시는 별도 짧은 활용편으로 제안한다. | R3 119–150행, U7 |
| 기존 검증 | 2026-09-09의 저장 기록은 PASS이며, 19단계·6개 폭·접촉·카메라·정지·종료 등을 검사한다. | 좌표 일치·사진 너비·검사 수는 사진 관계의 사실 정확도나 관객의 감상을 입증하지 않는다. | 기존 기술적 성취는 인정하고 이번 콘티의 의미·가독성·감상은 별도 확인한다. | R9, R13 |

**소급 결론: 이번 홍보 목적에 대한 INTENT GAP.** 과거의 **PASS / EXPERIMENT**는 당시 범위의 기록으로 유지한다. 이번에 기존 자동 검증을 재실행했다고 보고하지 않는다.

미확인 항목은 실제 사진에서의 검색 품질, 실제 모델의 검토 결과, 현재 실행 속도, 최종 Eevee 재질·렌더 시간, 1080p 동영상의 선명도, 관객 이해도와 감상이다.

## 3. 시간 순서의 시나리오

### 0–3초 — 작은 원 하나가 일을 시작시킨다

크림색 아틀리에. 햇빛은 종이 사진의 얇은 옆면과 푸른 Explorer의 둥근 굴곡에 걸린다. 공간 소개는 0.75초 안에 끝난다. ID 0이 화면 중앙보다 조금 오른쪽에 크게 서 있고, 붉은 원이 있는 라벨을 사용자의 작은 포인터가 누른다. 선택 테두리가 라벨을 포함한 병 영역에 생긴다. Explorer가 그쪽으로 몸을 기울여 사진 가장자리를 받친다. 화면 문구는 **“이 와인, 어디서 봤더라?”** 한 줄이다.

### 3–8초 — 찾은 목록과 본 사진은 다르다

Explorer가 선택한 영역의 작은 참조 조각을 도구 슬롯으로 밀어 보낸다. 슬롯에서 불투명한 후보 표식 두 개가 돌아온다. 사진도 판정도 아직 없다. Explorer가 표식의 모서리를 짚고 다시 슬롯에 넣는다. 이번에는 이미지 확인 요청이다. 응답 뒤 두 표식이 열리며 ID 4의 커피·디저트, ID 3의 거리 인물이 나타난다. Explorer가 두 장을 펼쳐 보고 Reviewer 쪽으로 넘긴다. 카페의 나무 테이블과 식기 같은 표면 단서는 보이지만, 이것이 실제 검색 순위의 원인이었다고 설명하지 않는다. 거리 후보는 검색 목록의 불확실성을 보여주는 짧은 예시다.

### 8–14초 — 맞지 않는 이유를 남긴다

호박색 Reviewer가 별도 비교 자리에서 원본 라벨을 먼저 보고, 카페 사진 전체를 본다. 다음 컷에서 원본은 같은 자리에 두고 거리 사진 전체를 본다. 둘 다 **“선택한 라벨을 확인할 수 없음”**이라는 범위의 판단이다. 렌즈는 얼굴이나 라벨 위에 올라타지 않는다. 두 후보는 옆으로 물러나지만 장면 안에 남는다.

Reviewer가 원본 라벨의 크림색 면과 붉은 원을 담은 작은 비교 조각을 Explorer에게 돌려준다. 후보의 실제 이미지도 옆에 남아 있다. Explorer는 받은 조각을 원래 선택 참조 옆에 끼워 넣고 다음 요청을 **“붉은 원 라벨의 와인병”**으로 구체화한다. 원본 사진과 선택 테두리는 바뀌지 않는다. 이 장면은 첫 제출이 모두 미지원·불완전이고 원본이 유효하며 예산이 남은 경우의 한 번의 귀환이다.

### 14–23초 — 같은 단서가 다른 장면에서 보인다

바뀐 요청이 나간 뒤에만 새 후보 표식이 돌아온다. 별도의 이미지 확인을 거쳐 ID 1의 식당과 ID 2의 매장 앞면이 열린다. Explorer가 관찰한 사진을 제출한다. Reviewer는 원본과 식당의 라벨, 이어 원본과 매장 라벨을 각각 비교한다. 공통으로 보이는 것은 **크림색 라벨의 붉은 원**이다. 같은 병을 샀다거나 같은 물리적 병이라고 결론 내리지 않는다.

검은 Organizer는 검토된 두 장만 받아, 식당을 조금 크게 앞에, 매장을 옆에 놓아 읽을 순서를 만든다. 문구·관계의 독립 확인까지 지난 다음에 배치가 정착한다. 두 사진 아래에는 **“붉은 원 라벨이 보이는 장면”**이 남는다. 원본 ID 0은 결과 목록 바깥의 출발 참조다.

### 23–33초 — 결과를 열자, 앞서 물러난 사진의 의미가 바뀐다

사용자가 식당 ID 1을 연다. 사진이 커지면서 와인 선택 테두리가 사라진다. 이제 얇은 프레임이 **사진 전체**를 감싼다. 사람·병·식탁·식당 배경을 모두 보여주고 카메라는 멈춘다. 짧게 **“사진을 열면, 함께 볼 이유까지.”**

새 맥락 작업에서 Explorer가 식당 전체와 그 사진의 설정 날짜를 확인하고, 별도 후보 목록을 받는다. ID 3·4 표식은 기존 옆자리에서 바로 결과로 점프하지 않고, 새 작업의 후보로 다시 확보된 뒤 전체 이미지가 열린다. 검은 Organizer가 식당을 중심으로 거리와 카페를 놓을 자리를 제안한다. 아직 관계선은 없다.

Reviewer는 식당과 각 후보의 전체 이미지, 설정 날짜와 제안 문구를 독립적으로 확인한다. 통과 뒤에만 **“같은 데모 설정 날짜 · 2026.06.14”**와 두 날짜 연결이 정착한다. 관객이 앞서 본 두 장임을 알아볼 수 있도록 카페·거리의 방향과 내용은 유지한다. 와인 관계의 미지원은 그대로다. 새로 확인된 것은 같은 설정 날짜라는 별개의 관계다.

### 33–43초 — 이번 관심은 사용자가 바꾼다

식당 사진을 정면으로 다시 잡는다. 포인터가 와인이 아니라 사람의 얼굴을 명시적으로 누른다. 사진 전체 프레임은 물러나고 사람 선택 영역이 생긴다. **“이번에는, 이 사람의 다른 날.”** Explorer가 새로운 선택에 반응한다.

짧아진 기존 문법이 이어진다. 요청 → 후보 표식 → 이미지 요청 → ID 3·5 전체 사진 관찰 → 제출 → 원본의 선택 인물과 각 후보를 독립 비교. 새로운 탐색에서는 이 두 사진이 확인되는 가상 사례다. 인물 관계나 이름을 입력받는 장면은 없다. 검토와 결과 정리를 거친 뒤 사용자가 ID 5를 열면, 바닷가의 푸른 색이 프레임을 크게 채운다. 사진 속 공간을 가상의 3D 해안으로 만들어 통과하지 않는다.

### 43–50초 — 도착한 사진이 다시 중심이 된다

바닷가 사진 전체를 기준으로 별도 자동 맥락을 준비한다. 사람뿐 아니라 바다·난간·야외 장면까지 한 번에 보여준다. 추가 후보 ID 1·3을 새 맥락 작업에서 확보하고 전체 이미지를 관찰한다. 검은 캐릭터가 배치를 제안하고, Reviewer가 원본·멤버·문구를 다시 확인한다. 이 장면에서는 새 기준에서 인물과 다른 설정 날짜의 관계가 유용하게 남는 가상 사례다. 바다·장소 관계를 억지로 추가하지 않는다.

ID 5가 중앙에 가장 크게, 식당과 거리 사진이 주변에 정착한다. **“이 사람이 보이는 다른 장면”**, 날짜는 **“데모 설정 날짜: 바닷가 04.18 / 식당·거리 06.14”**로 읽힌다. 카페는 새 맥락의 구성원으로 들어오지 않는다. ‘그날’이던 구성에서 ‘다른 날의 인물’로 읽을 이유가 바뀐다.

### 50–54초 — 지나온 길과 이름을 남긴다

0.75초 안에 카메라가 짧게 물러난다. 출발 와인, 열었던 식당, 도착한 바닷가가 읽을 크기로 남고 매장·거리·카페는 작은 옆가지에 자리한다. 서로 관계 없는 사진을 모두 잇지 않는다. 51.5초에 엔드카드로 하드 컷한다.

제품명 **Connected Gallery**, 카피 **사진 한 장에서, 다음 기억으로.**, 그 아래 **Made with Astra · Blender / Eevee**. 마지막 2.5초 동안 세 줄은 움직이지 않는다. 이는 후속 영상의 제작 크레딧 계획이며 현재 완성 영상의 제작 실적을 주장하는 문장이 아니다.

## 4. 샷 리스트

### 공통 촬영 문법

표의 시간은 최종 타임라인상의 연속 구간이다. 전환·움직임·판독 시간은 **그 숏 안에 포함**하며 덧붙이지 않는다. 하드 컷은 0초, 매치 연결은 기본 0.25초(6프레임), 필요시 0.5초(12프레임)다. 장면 간 이동은 최대 0.75초를 출발값으로 한다. ‘판독’은 카메라가 정착하고 결정적 사진·문구가 함께 읽히는 최소 목표 시간이다. 동작 중 보인 시간으로 대체하지 않는다.

빛 표기 W는 따뜻한 크림색 확산광, A는 W에 더해 유리 가장자리만 호박색으로 강조, B는 W를 유지하되 사진 속 바다의 푸른 색과 약한 반사광을 살리는 구도다. 조명의 색은 판정을 뜻하지 않는다. 승인 여부는 비교 완료 후의 상태 변화로 보인다.

아래 도구명과 ID는 **제작 메모용**이다. 실제 화면에는 표시하지 않는다. 후보 표식은 불투명한 작은 직사각형, 관찰한 사진은 열린 앞면, 검토 완료는 종이 하단의 작은 표식과 정착으로 구별한다. 색만으로 상태를 전달하지 않는다. 요청·관찰 표식과 사진 간 관계선도 형태를 달리한다.

화면 하단 안전 영역에는 **“생성 사진 · 가상 날짜 · 고정 시나리오”**를 지속 표시한다. 상태·근거의 짧은 보조 표기와 별개로 큰 핵심 문장은 한 번에 하나만 둔다. 신뢰도 %, 도구명, 모델명, 토큰·예산·타이머는 화면에서 제외한다.

### 안무가 구현 의미와 어긋나지 않게 하는 제작 메모

1. **S09 조건**: `runner.py`의 첫 검토에서 `items=[]`, `complete=false`, 원본 선택 유효, 검토 횟수 조건, 충분한 남은 응답·도구 예산이 모두 맞는 사례다. 코드에는 `attempts < 2`, `turns < turns_limit - 1`, `calls < max_calls - 2` 조건이 있다. 시간 제한도 원래 실행 안에 있다. 일부 통과 후 같은 귀환, 무한 반복, 성공을 위한 예산 증가는 표현하지 않는다. 숫자는 제작 메모에만 둔다. [R10]
2. **S15·S24c의 정리**: ResultOrganizer는 독립 검토된 후보만 받아 관계·문구를 제안하고 별도 검토한다. 새로운 후보를 확보하는 캐릭터로 보이지 않게 한다. 54초 개정에서 사람 비교 S24a·b와 정리 S24c를 분리했다. 러프 편집에서 여전히 정리·확인 순서가 겹쳐 보이면 이 숏을 늘리고, 비교를 삭제해서 시간을 맞추지 않는다. [R11]
3. **S17–S20 / S26–S29**: 검은 캐릭터를 자동 맥락의 관계 구성 은유로 재사용하되, 전체 기준·새 후보 확보·전체 이미지 응답·제안·독립 검토를 명시적으로 다시 거친다. Explorer는 이 별도 작업의 도구 선택·관찰을, Reviewer는 독립 확인을 표현하는 시각적 배역이다. 세 캐릭터가 항상 세 개의 동일한 백엔드 프로세스로 실행된다는 뜻은 아니다. [R12]
4. 맥락의 전체 이미지 관찰은 `inspect_photos` 또는 획득한 미관찰 후보를 실제로 열어 주는 `plan_photo_context`에 대응할 수 있다. 후자를 별도의 무조건적인 추가 이미지 읽기로 묘사하지 않는다. 이미 전체 관찰한 사진은 같은 작업 안에서 불필요하게 다시 읽지 않아도 된다. 이번 이야기의 서로 다른 작업에서는 새 관찰·검토의 경계를 보여준다. [R12]
5. 맥락의 시각·문구 독립 검토는 한 호박색 안무에 압축할 수 있다. 두 검토가 완료된 뒤에만 관계·문구를 확정한다. 이번 안에서는 한 번에 통과하는 사례로 두고 Connect의 조건부 재탐색과 혼합하지 않는다. [R12]
6. 후보 표식의 연결은 도구 왕복 표시이며 사진 관계선이 아니다. 실제 관계선은 해당 주장 검토 후에만 나타난다. 검토 중에는 종이 위치만 제안할 수 있고, 확인되지 않은 선은 그리지 않는다.
7. 무음 이해를 우선한다. 대사는 기본안에 없다. 효과음은 직접 녹음한 종이·유리·돌 소리나 출처가 확인된 무료 자산으로 준비한다. 음악은 자체 제작 또는 이용 조건을 확인한 무료 음원으로, 특정 서비스나 유료 라이선스를 전제하지 않는다. 실제 출처는 제작 시 기록한다.

## 7. 자산 계획과 제작 가능성

### 기존 자산으로 가능한 범위

| 자산 | 이번 계획의 사용 | 새 자산 최소 수·상태 |
|---|---|---|
| `gallery.png` 본편 6장 | 전 장면, 동일 라벨 조각·얼굴 인서트, 관계와 기준 변화 | **새 사진 0장으로 본편 성립.** 인서트는 동일 사진 재사용이며 새 장수로 세지 않는다. |
| `concept.png` | 세 캐릭터, 따뜻한 빛, 유리 두께·종이·돌의 재질 기준 | 참조용. 이미지 속 다른 풍경 사진은 본편 관계 근거로 사용하지 않는다. |
| 발표 내 인형 3장 | 별도 활용편의 ‘여러 순간의 물건’ 후보 | 신규 사진 불필요. 같은 물리적 인형·소유·사용 기간의 단정은 별도 검수 대상. |
| 발표 내 카페 계절 3장 | 별도 활용편의 장면 변화 비교 | 신규 사진 불필요. 본편의 커피 사진 ID 4와 같은 카페라고 연결하지 않는다. |
| HTML/CSS 가상 안내문 3페이지 | 별도 활용편의 제목·발행 월·페이지 번호 비교 | 새 문서 내용 불필요. 후속 제작에서 기존 문서를 출력용 자산으로 변환한다. |
| 사진 카드·요청 표식·날짜 표지 | 간단한 종이·도형으로 제작 | 신규 사진이 아닌 제작용 물체. 이번에는 만들지 않았다. |
| 음원·효과음 | 종이, 유리, 돌, 짧은 요청·응답, 발견의 화성 | 아직 선정·녹음하지 않았다. 무료 이용 조건과 출처를 제작 시 기록. |

**해상도 확인:** `gallery.png`는 1774×887, `concept.png`는 1536×1024였다. 3×2 시트의 사진 한 장은 경계 반올림을 고려하면 약 591×444다. 1080p의 큰 사진과 라벨 확대에서 선명도 여유가 작다. 흰 테두리나 그림자를 선명하게 만드는 것만으로 사진 내부 디테일이 복구되지는 않는다.

우선 기존 사진의 전체 구도와 붉은 원처럼 실제로 읽히는 큰 특징을 쓴다. 작은 글자 판독·극단적 얼굴 확대·생성 업스케일로 새 세부를 만드는 연출은 기본안에 없다. 제작 때 더 큰 동일 원본이 있는지 확인하고, 없으면 대표 프레임에서 확대 한계를 먼저 판단한다. 이 해상도 문제가 곧바로 ‘새 사진이 필요하다’는 뜻은 아니다. 부족하면 사진 전체 크기와 인서트 배치를 조정하고, 의미 전달이 약해지는 교환 조건은 사용자와 확인한다.

### 선택안: 헷갈릴 만한 후보 한 장

추가 생성 사진 **최소 1장**을 선택안으로만 제안할 수 있다. 목적은 비슷한 크림색 라벨을 가진 **다른 와인병**을 보여주어 첫 독립 비교의 판단을 더 미묘하게 만드는 것이다. 원본과 구별되는 단서가 실제 이미지에 있어야 한다. ‘다른 물리적 병’인지만으로 미지원이라 하지 않고, **선택한 라벨과의 연결 주장이 뒷받침되지 않는 차이**를 보여준다.

채택하더라도 첫 후보 3·4를 교체하지 않는다. ID 6을 추가하고 첫 검토의 세 후보를 모두 미지원으로 유지한다. 새로운 비교·피드백 판독에 약 2–3초를 더 배정해야 한다. 이 안은 최초 검색의 설득력을 높일 수 있지만, 재등장해야 하는 3·4의 기억과 러닝타임을 분산시킨다. **본안에는 넣지 않는다.** 실제 러프 편집에서 첫 후보가 너무 무작위라는 피드백이 반복될 때 재검토한다. 지금 이미지를 생성하지 않는다.

### 문서·인형·계절의 사용처

| 선택지 | 장점·교환 조건 | 제안 |
|---|---|---|
| 본편 안에 모두 포함 | 활용 범위는 넓게 보이지만 기준 변화의 핵심 장면이나 판독 시간을 밀어낸다. | 채택하지 않음. 자산 부족이 아니라 메시지 선택. |

별도 활용편도 고정 예시임을 밝히고, 본편 와인·사람의 관계를 증명하는 자료로 섞지 않는다. 주변 갤러리를 풍부하게 보이게 하려고 6장을 수백 장으로 복제하지 않는다. 본편에서는 한 장 한 장의 내용과 역할 변화로 풍부함을 만든다.

### 후속 Blender 제작의 범위

사용자 제공 환경은 Windows, RAM 약 64GB, RTX 3050 6GB, Blender/Eevee 소형 테스트 성공이다. 이번에 설치·드라이버·자원·벤치마크를 다시 확인하지 않았다. 54초×24fps는 **1296프레임**이며, 이것은 타임라인 계산일 뿐 렌더 비용 예측이 아니다.

한 아틀리에 세트와 소수의 카드·단순 캐릭터를 쓰고, 텍스처 공유·인스턴스·샷별 가시성을 활용한다. 사진의 실제 비교 장면에서는 이미지에 강한 반사와 깊은 그림자를 얹지 않는다. 유리 재질 검수는 사진을 가리지 않는 가장자리 반사·두께에 집중한다. 연기, 유체, 대량 고유 지오메트리, 고해상도 배경을 기본 요구로 하지 않는다.

영상 제작을 별도로 요청받은 뒤에는 대표 정지 화면 → 낮은 해상도 연속 편집 → 최종 해상도 순으로 확인한다. 편집 가능한 `.blend`, 재현 스크립트, 사용 자산·음원 출처, 이미지 시퀀스와 MP4를 남기는 구조로 설계한다. 이후 저장소 변경은 전용 worktree·branch에서 검증·커밋·푸시하되 기존 자료와 worktree를 보존한다. 이번 기획에는 그 저장소 변경을 실행하지 않았다.

## 8. 미결정 사항

이번 기획을 완성하는 데 추가 답변이 필요한 사항은 없다. 제작 전 사용자가 선택할 중요한 편집 결정은 아래 두 가지다.

| 결정 | 이번 권장안 | 다른 선택의 영향 |
|---|---|---|
| 본편 길이 | **54초**. 핵심 비교·새 기준·별도 맥락 관찰을 유지 | 45초 상한이 필요하다면 러프 편집에서 판독 시간을 확인하며 다시 설계해야 한다. 의미 삭제로 맞추지 않는다. |
| 내레이션 | **없음**. 세 핵심 카피와 관계 근거, 행동·음악으로 전달 | 필요하면 시작·맥락 전환·끝의 짧은 내레이션을 추가할 수 있다. 도구 단계마다 설명하는 내레이션은 별도 리듬 검토가 필요하다. |

추가 사진은 0장, 확장 사례는 별도 활용편, 기존 캐릭터·따뜻한 미술, 빠른 컷, 크레딧 표기는 본안의 명확한 제안으로 두었다. 지금 작은 구현 선택을 사용자 질문으로 넘기지 않는다. 별도 활용편 자체의 제작은 이번 범위에 포함하지 않는다.

## 9. 검증 계획과 현재 증거의 대응

현재 제출물은 **EXPERIMENT 시나리오**다. 문서에서 처리 순서와 근거 범위를 점검하는 것과, 실제 관객에게 전달되는 것은 다른 주장이다.

**기획 단계 자기검토:** 의도 충족은 세 흐름과 발견을 모두 시간선에 배정했다는 문서 수준에서 확인했다. S24의 비교와 정리는 54초 개정에서 분리했다. 후반의 짧은 반복 안무가 실제 관객에게 읽히는지와 원본 사진 해상도는 제작 관찰 대상으로 남는다. 의도 초과는 새로운 고정 분류·성공 보장·임의 후보 추가·유료 도구 전제가 없는지 원장과 대조했다. 프로젝트 정렬은 R1·R2·R10–R12를 기준으로 검토했다. **가설 리뷰 SOUND / 분류 EXPERIMENT. 영상 구현 리뷰는 미실시이며 PASS를 부여하지 않는다.**
