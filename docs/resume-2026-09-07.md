# Connected Gallery — 2026-09-07 재개 검증

기존 중단 기록은 `handoff-2026-09-07.md`다. 386장 분석 상태에서 재개했다. 아래는 개발 중의 기록이다. 최종적으로 1,000장 분석·필수 인덱스, Spaces와 실제 Android 흐름을 확인했으며 최종 결과와 남은 품질·속도 한계는 `final-mvp-validation.md`에 정리했다.

## 최신 범위와 Connect 수정

사용자가 Timeline/Time을 후속 기능으로 미뤘다. 현재 MVP와 Goal은 Organize + Connect이며, 아래 Time 실험은 과거 검증 기록이다. Time 재시험은 이번 완료 조건이 아니다. Android의 Time 버튼을 제거했고, 저장된 현재 화면·뒤로 가기 이력의 연도 필터와 해당 필터의 결과를 이관한다. 필터 없는 화면의 결과·스크롤은 보존한다. 후속 작업은 CG-15다.

Spec 8에서는 실제 사물 검색 실패 한 건의 앞단 원인을 확인했다. 객체 탐지의 픽셀 좌표는 맞았지만 분석에 저장된 상대 좌표가 달라 선택 crop이 바닥을 가리켰다. 도구가 실제 입력 이미지 크기로 좌표를 정규화하고 crop 좌표를 전체 사진으로 변환한다. 얼굴 crop 좌표도 전체 사진 기준으로 반환한다. 에이전트는 의미를 판단해 근거 영역을 선택하며 숫자를 다시 추정하지 않는다. 선택 crop에 전체 사진 설명을 붙이지 않도록 해 화면 밖 사물이 선택 대상으로 오인되는 것을 줄인다. 마지막 응답의 incomplete 결과는 예산 오류로 버리지 않는다.

확인된 기존 영역 1건은 별도 모델이 실제 탐지 crop 중 대상을 선택해 수정했다. 원래 설명·영역 ID·필수 인덱스는 보존했다. 수정 전 후보의 독립 비교는 일치 1/불일치 2였고, 수정 후 실제 Android 새 검색은 4장을 반환해 네 장 모두 대상 사물이 보임을 이미지와 별도 모델로 확인했다. 최초 서버 결과 37.84초, 완료 37.92초다. 단일 사례이며 라이브러리 전체 정밀도나 15초 목표 달성을 뜻하지 않는다. 다른 기존 영역의 좌표를 모두 수정했다고 주장하지 않는다. 서버 테스트는 41개 통과했다. 현재 세부 집계는 `connect-mvp-validation.json`이다.

사진 표시 후 분석 영역이 도착할 때 탭이 처음의 빈 영역 목록을 계속 사용하는 문제를 실제 기기 테스트로 재현했다. 제스처 처리기가 최신 영역·콜백을 읽도록 `rememberUpdatedState`를 적용했다. 확대 상태를 다시 만들지 않는다. SM-S918N/Android 16에서 맞춤 이미지 영역 탭, 확대 후 중심 길게 누르기, 늦게 도착한 분석·콜백 갱신의 3개 테스트가 ADB AndroidJUnitRunner로 통과했다. Gradle 기기 실행기는 별도 logcat 연결 timeout을 겪었으며 테스트 통과로 바꾸지 않는다. assembleDebug, 단위 테스트, lintDebug도 통과했다.

동기화 응답에 요청 사진의 분석 스냅샷과 활성 작업 목록을 포함해 이미 준비·대기 중인 사진마다 GET/POST를 반복하지 않는다. Android의 사진·분석 캐시 저장도 묶어서 처리해 사진 Flow가 장수만큼 갱신되는 것을 줄인다. 구 서버의 응답에는 기존 조회 방식을 유지한다. 서버 계약 테스트는 다른 사진 분석의 제외, 버전 변경 분석 무효화와 활성 작업 표시를 확인한다.

## 안정성 변경

Spec 10–12에서는 독립 검증이 모든 후보를 거절하되 원래 선택 영역은 유효한 경우, 남은 기존 실행 예산 안에서 검증 근거를 전달해 한 차례 검색을 보완한다. 잘못된 선택 영역은 재검색으로 숨기지 않는다. 대화형 모델 호출은 시도 전체를 15초로 제한하고 기본 모델 1회 뒤 설정된 대체 모델 1회를 허용한다. 전체 탐색 제한은 90초다. 취소하면 대체 호출을 시작하지 않는다. 이 변경으로 제공자 지연이나 실패가 사라졌다고 주장하지 않는다.

실제 API 재시험에서 사물은 31.05초에 3장, 텍스트는 88.32초에 2장을 독립 검증 후 반환했다. 사람은 후보 4장 모두 검증을 통과하지 못해 65.09초에 빈 incomplete 결과였다. 다른 사물 실행은 모델 시간 초과로 실패했다. 각각 `independent-review-validation.json`, `evidence-refinement-validation.json`, `target-types-validation.json`에 성공·실패 기록을 함께 보존한다. 이는 작은 회귀 표본이며 전체 정밀도·p95 또는 최종 기기 수용 검증이 아니다.

선택 영역 검색에 전체 사진 벡터만 사용되던 공백을 확인했다. 이제 분석을 저장하기 전에 전체 이미지·설명/OCR 텍스트·에이전트가 선택한 각 영역의 벡터를 준비한다. 같은 영역은 재사용하고 전체 화면 영역은 전체 사진 벡터를 공유한다. 검색은 사진마다 가장 높은 점수를 먼저 고른 뒤 상위 사진 수를 제한해 한 사진의 여러 영역이 후보 수를 소진하지 않는다. 기존 분석은 `/assets/{id}/reindex`와 `scripts/repair-missing-indexes.py`로 보존하며 보충한다. 준비 완료 집계에 선택 영역을 추가했으므로 예전 이미지/텍스트 완료 수와 구분해야 한다. 좌표·설명 수정 시 낡은 파생 벡터를 같은 트랜잭션에서 제거하며 독립 crop·얼굴 벡터는 보존한다. OCR도 실제 입력 크기와 crop 위치로 정규화된 영역을 반환한다.

현재 서버 테스트 55개가 통과했다. 인덱스 중복·전체 화면 재사용, 영역/텍스트 수정, crop 인덱스 실패 시 원자적 저장, 사진별 후보 중복 제거, OCR 좌표, 검증 근거에 따른 재검색과 모델 호출 시간 제한을 포함한다. 실제 1,000장 동기화 스냅샷 API는 0.36초에 완료됐다(`sync-snapshot-validation.json`). Android 동기화 전체 시간으로 해석하지 않는다. 실행 후보와 독립 판정의 상세 근거는 비공개 로컬 DB에만 남기고 공개 보고에는 개수·시간만 기록한다.

Spec 9는 Explorer 최종 후보를 원래 선택 대상과 별도 모델 문맥에서 다시 대조한다. 검색 대화의 추론·전체 사진 설명·기존 선정 이유는 검증 문맥에 넘기지 않는다. 선택 의미 힌트와 실제 이미지로 직접 관련성을 판단하고, 지원되는 후보만 결과 이벤트와 캐시에 기록한다. 동일 사물과 직접 관련된 다른 형태를 구분하며 Related와 Same moment의 조건도 분리한다. 검증 오류·취소·누락 또는 중복 판정은 미검증 후보를 통과시키지 않는다. 전부 거절되면 빈 incomplete 결과다. 의미 필터를 고정 분류나 키워드 규칙으로 대체하지 않는다. 기존 90초 실행 제한을 공유하며 추가 모델 비교 시간도 측정한다. 검증 전 결과 비노출, 후보 제외, 잘못된 crop, 판정 계약 위반, 취소의 회귀 테스트를 포함해 서버 46개 테스트가 통과했다. 실제 API 재시험은 진행 중이며 휴대폰이 패턴 잠금으로 바뀌어 이후 기기 검증에는 사용자 해제가 필요하다.

- 분석 근거·필수 벡터·실행 완료 결과를 같은 SQLite 트랜잭션에 저장한다. 이후 체크포인트 정리 오류가 성공한 분석을 실패로 바꾸지 않는다. 취소된 실행이면 트랜잭션 전체가 롤백된다.
- 같은 체크포인트 DB를 사용하는 saver의 짧은 DB 연산을 공유 잠금으로 직렬화한다. 모델 응답과 도구 실행은 동시 처리한다.
- 실행 오류에는 예외 유형, SQLite 오류 코드/이름, 함수·파일·줄 번호만 기록한다. 사진·SQL·모델 입력·키는 진단에 복사하지 않는다.
- 이전 OperationalError 1건은 정확한 메시지가 보존되지 않아 원인을 확정할 수 없다. 저장 후 체크포인트 오류를 주입한 회귀 테스트에서 결과 보존을 확인했지만, 과거 오류와 같은 원인이었다고 단정하지 않는다. 과거 실패 기록도 성공으로 덮어쓰지 않았다.
- 사진 삭제 동기화와 정상 종료 시, 관계없는 대기 작업은 queued로 보존한다. 삭제된 사진에 연결된 실행은 정확한 JSON ID로 찾는다. 부분 문자열 검색으로 다른 작업을 지우지 않는다.

## 탐색 변경

- 첫 모델 요청에 선택 사진 또는 crop과 라이브러리 규모를 첨부한다. 에이전트가 인덱스 범위를 알고 검색 도구를 선택할 수 있다.
- Related는 선택한 대상을 유지하고, 결과 수를 채우기 위해 주변 공간·생활 맥락으로 의미를 넓히지 않도록 지침을 명확히 했다. 의미 판단·후보 검증·최종 선정은 모델이 수행한다.
- 서버 캐시는 agent spec 7과 retrieval policy로 구분한다. Android도 기준 사진이 포함된 이전 결과를 사용하지 않고 서버 revision/spec 변경 시 캐시를 갱신한다.
- `CG_EXPLORE_TIMEOUT_SECONDS` 기본값을 90초로 설정하고 서비스·도구가 동일한 제한을 사용한다. 허용 범위는 15~180초다. 초기 45초 제한에서 실제 휴대폰 탐색이 시간 초과했다. 제한 완화는 속도 개선 증거가 아니며, 최초 5초·최종 15초 목표는 미달 상태다.

## 현재까지 검증

- Python 테스트 **35개 통과**. 저장 후 실패 보존, 취소 롤백, 동시 모델 진행, 이전 캐시 배제, 최초 선택 crop 전달, 삭제 시 다른 대기열 보존, 공통 제한 시간, 후보 확인 뒤 원래 anchor 이미지 재제시를 포함한다.
- Android 최종 assembleDebug / testDebugUnitTest / lintDebug 통과 후 APK 설치. 캐시 spec 갱신 변경도 포함한다.
- 실제 Android에서 세 번의 대상 선택·탐색 결과 표시를 확인했다. 결과는 3/1/4장, 서버 처리 시간은 13.18/87.71/49.03초였다. 중간 시간 초과와 수정 후 재시도가 포함돼 오류 없는 연속 3hop 성공이나 UI 렌더링 지연 측정으로 해석하지 않는다. 기준 사진이 결과에서 제외되는 것을 확인했다.
- Time은 동일 anchor·2024년 조건으로 7장을 반환했지만, 선택한 사람과 무관한 맥락으로 바뀌어 의미 유지 검증에는 실패했다. 서버에 저장된 실제 입력 crop은 정상임을 확인했다. spec 7은 매 후속 모델 응답에 원래 anchor 이미지와 불변 조건을 다시 제시한다. 단일 사례의 후속 재시험과 일반 품질 평가는 구분한다.
- 빠른 연도 변경 후 이전 실행 취소와 최종 2024 표시를 확인했다. 뒤로 가기 세 번으로 연도 변경 이력을 지나 기존 전체 연도 결과 4장이 복원됐다.
- 상세 집계는 `android-resume-validation.json`, 최신 인덱스·대기열 상태는 `resume-progress.json`에 있다. 전체 사진 분석·최종 Spaces·P@5·Find 성공시간·재사용 의향 평가는 아직 완료되지 않았다.

## Spec 7 Time 재시험의 한계

동일한 실제 anchor로 Android에서 2024년을 다시 선택했다. 입력 anchor와 반환 연도 조건은 유지됐고 서버 실행은 completed였지만, 선택한 사람과 무관한 대상이 결과에 섞였다. 원래 crop을 매 모델 판단에 다시 제시하는 보완만으로 의미 유지 문제를 해결하지 못했다. 따라서 Time 기능을 제품 수용 기준 통과로 표시하지 않는다. 다음 단계에서는 기준 대상과 최종 후보를 독립적으로 대조하는 모델 검증 방식 및 실제 대상별 평가셋을 검토해야 한다. 원래 목표인 완벽한 인물 ID는 범위 밖이지만, 무관한 대상·맥락으로 이동하는 문제는 남은 핵심 품질 과제다.

서버는 중단하지 않고 남은 분석을 계속 처리한다. 최종 Organizer도 분석 대기열 뒤에 등록했다. 과거 failed/cancelled 실행 건수는 현재 미분석·실패 사진 수와 다르다. 현재 사진별 누락 여부는 `uncovered_photo_count`를 확인한다.

## 검증 중 발견한 갤러리 동기화 문제

검증 캡처를 공용 저장소에 저장하면서 최근 1,000장 목록에 캡처가 편입됐다. 생성한 파일을 제거하고 미디어 목록 갱신 후 원래 1,000장 목록과 초기 분석 386장의 보존을 확인했다. 이후 화면 캡처는 `/data/local/tmp`만 사용한다. 이 과정에서 사진 한 장의 목록 제외가 전체 대기열을 취소하는 문제를 발견해 수정했다. 분석 결과도 활성 작업도 없는 사진을 API로 다시 등록해 누락 0장을 확인했다.

실제 사진·실행 ID·화면 캡처는 Git에서 제외한 `work/`와 `.runtime/`에만 둔다. 공개 결과는 집계치만 기록한다.
