# Space 제외 구현·검증

2026-09-07 · 기준 커밋 `ceca302` · 사진 상세의 새 자동 맥락 UX와는 별도 변경이다.

## 반영한 동작

- Android의 Spaces 탭·모으기·공간 선택/편집·주기적 조회를 제거했다. 사진 목록에서 바로 탐색을 시작한다.
- `feature-spaces` 모듈과 앱 의존성, Android Space 모델·저장소 메서드·관련 네트워크 호출을 제거했다.
- 분석 완료 후 전역 Organizer를 자동 시작하지 않는다. 새 Organizer 요청은 API에서 HTTP 410으로 거절하고 서비스 계층에서도 차단한다. 완료된 과거 요청의 idempotency key를 다시 보내도 재사용되지 않는다.
- `/spaces` 목록 API를 제거했다(HTTP 404). Space 포함·제외 피드백은 HTTP 410으로 거절하며 Space나 피드백 데이터·revision을 변경하지 않는다.
- 서버 재시작 시 기존 queued/running Organizer 작업을 cancelled로 전환하고 사유를 남긴다. 해당 작업의 기존 결과와 Spaces는 삭제하지 않는다. 분석·탐색 작업은 기존대로 복구한다.
- 활성 Explorer에는 `read_spaces` 도구를 제공하지 않는다. 사진·영역 관찰, 시간·이미지 등 후보 검색과 에이전트의 의미 판단은 유지한다.
- 도구 구성이 바뀌었으므로 health·서버 탐색 캐시 키·runner checkpoint의 agent spec을 16으로 함께 변경했다. 이전 도구 상태로 실행을 재개하거나 구버전 결과 캐시를 최신 정책으로 오인하지 않는다.

## 데이터와 호환성

개인 사진·분석·벡터·DB를 이 작업에서 수정하지 않았다. 변경과 검증은 기준 커밋의 격리된 소스 복사본에서 수행했고, 테스트에는 임시 DB와 모의 runner/model을 사용했다. 유료 모델 요청을 실행하지 않았다.

기존 서버의 Space 저장 스키마·내부 타입·과거 검증용 도구/runner는 이력 호환을 위해 남긴다. 앱·공개 API·실행 서비스에서 새 Space를 생성하거나 편집하는 경로는 차단한다. 기존 데이터의 삭제나 마이그레이션은 포함하지 않는다. 기존 사진 삭제 시 연결된 파생 데이터 정리 동작은 유지한다.

연결 결과와 맥락의 내부 저장·캐시는 Space와 독립적으로 유지한다. 정책 버전이 달라지면 기존 캐시를 다시 계산할 수 있으며, 이는 Space 저장 기능 재도입이 아니다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| Python 전체 회귀 | 71개 통과, Starlette deprecation 경고 1개 |
| 추가 Space 제외 회귀 | 새 생성·편집/목록 차단, 과거 완료 요청 재사용 차단, 마지막 분석 완료 후 자동 생성 없음, queued/running Organizer 복구 차단, 분석·탐색·저장 근거 보존, 활성 도구 범위 확인 |
| Android | `assembleDebug`, `testDebugUnitTest`, `lintDebug` 모두 성공 |
| Android JVM 단위 테스트 | 9개 통과, 실패·오류 0개 |
| Android lint | 오류 0개, 경고 6개(백업 설정 1, kapt 1, KTX 권고 4) |

Android는 기존 로컬 Gradle 의존성을 사용해 `--offline`으로 빌드했다. APK는 생성했으며 휴대폰 설치·실제 화면 터치·실기기 3hop은 이번 검증에서 수행하지 않았다. 실행 중인 개인 서버도 이 작업에서 재시작하지 않았다. 동작 적용에는 업데이트된 서버 실행과 새 APK 설치가 필요하다.

## 남은 범위

이번 완료는 Space 제외 코드다. [제품·UX 문서](connected-gallery-product-ux.md)의 ‘사진을 열면 주변 맥락이 함께 보이는 경험’과 기존 결과 그룹핑 데모의 main 통합은 아직 별도 작업이다. 따라서 CG-11 전체나 새 Organize UX가 완료됐다고 표시하지 않는다.
